## Learnings from the run

- **Dependency-ready is not execution-ready.** Read the native body and subsequent comments, validate imported metadata, and check access/date gates. Repeating the same “seven ready” snapshot cannot clear an intake failure. GC traced the immediate UI failure to the importer dropping `ui:` despite its presence in Jira, and restored the three lines; source parsing and the final intake gate both need checking. The UI shell/reference became the main dependency bottleneck despite spare RAM.
- **Secure the real integration inputs early.** Configured managed PostgreSQL would unlock two substantial retained implementations and provide the missing foundation proof. Source-use decisions and compatible GB/RHD contexts constrain the demo data path. More agents cannot substitute for these inputs.
- **Real fixture integration found bugs that small checks missed.** Generated/published/loaded E2E found that a legitimate source-citation URL query was being rejected by an asset-style validator; citation handling was corrected while asset URLs remain strict. Policy review found/fixed scheduled-successor publication losing pending edits; the earlier passing full was explicitly superseded and rerun after the regression fix.
- **One versioned policy source avoids divergent assumptions.** Use `server/gcsp/policy/seed-v1.json` only through `server/gcsp/policy/index.js` PolicyService; 83 supplies the pending SQL provider through that port. Keep plausible values labelled, coherent and easy to revise, rather than waiting for every policy answer or copying defaults into consumers.
- **Validation needs a concrete identity and scope.** Start with affected regressions/callers, serialize full suites and shared merges, and reuse evidence only for identical code/inputs/environment. Put `--test-concurrency=1` **before** the test glob; an option after the glob was an earlier pitfall. Strict stamp reproduction requires the complete saved replacement environment and dependency/tool pins, not a digest plus inherited environment. A full backend pass with native skips is not native acceptance or a full demo pass.
- **Resource ownership and cleanup need evidence.** Bounded one-worker chunks, ownership manifests, host reservations, supervisor finalizers and independent absence checks supported stable progress. A stopped PID does not prove scratch deletion; sequential peak allocations are not deletion totals. Preserve portable summaries and bounded useful failure evidence instead of successful verbose output trees.
- **Model routing was explicit, but efficiency was not measured.** Leads/reviewers generally requested Sol/high, implementers Sol/medium, runners Luna/high through the installed tier resolver. Requested model/effort was recorded; effective runtime selection and Advantage Credits per completed story were not independently verified. Do not turn 31 completions into a cost or model-quality comparison without comparable evidence.
