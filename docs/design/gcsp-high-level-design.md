## Purpose and constraints

Build the complete, working GCSP experience through replaceable adapters while preserving the [demo brief's binding purpose and boundaries](../gcsp/demo-brief.md#binding-boundaries), [build rules](../gcsp/build-rules.md), [experience quality contract](../gcsp/experience-quality.md) and [component decisions](../../COMPONENTS.md). Synthetic source preparation is explicit and separate from business services; no fabricated source facts or per-person outcome scripts replace working state transitions. Real BMW integration requires its actual contracts/access and is not established by substitute acceptance.

GCSP alone migrates. Used Cars retains its frontend, Node backend, brand/link/API/export contracts and supported shared consumers. Angular 21 owns GCSP screens/navigation. Java 21 with Quarkus 3.x owns GCSP APIs, business execution, inference and runtime jobs without invoking Node business code. Offline corpus generators/trainers may remain JavaScript. Exact compatible package/tool versions are pinned by the foundation Stories, not invented here.

Real test OIDC browser login and bearer JWT replace the demonstration identity authority. Employees and Greg use their own logins; presenter operates scenarios/clock/releases/reset/faults/retry and permitted inspection, with no impersonation or employee/Greg commands. Greg retains comparison commands. Legacy GCSP URL/API compatibility is unnecessary. Implemented business outcomes and current visual design are otherwise the baseline.

## Identity, API and recovery

`GET /api/gcsp/v1/context` is the first connected interface between foundations. A valid bearer access JWT resolves `{subject, roles, environmentId, runId, employeeId?, policyVersion, capabilities}` inside `{status:"ok",value:...}`. Signature, issuer, audience and lifetime are checked by Java; trusted mappings determine roles/employee identity. Unknown mappings refuse rather than selecting a fictional employee. Frontend route guards/capability visibility help navigation; server role and resource-ownership checks remain authoritative.

New offer links target `/gcsp/offers/:offerId`, require sign-in and return to the authorised owned offer. Opaque lookup material grants no authority. Renewal is supported where possible; otherwise sign in and return with saved progress. Authentication recovery must not automatically submit an unfinished order. Sign-out clears application authentication/private state and ends the provider session where supported so another account can sign in.

The [operation inventory](../gcsp/migration-baseline-2026-11-13/inventory.json) maps all 100 source method/path operations to Stories. The initial replacement is the same method/semantic suffix under `/api/gcsp/v1`, except real OIDC replaces session login/logout, principal switching is removed, link-only offer session authority is removed, deprecated brief pause/resume aliases are removed, and comparison commands are Greg-only. The [API contract](../gcsp/migration-replacement-contracts-2026-11-13.md#browser-and-api-surface) records browser routes and each operation family. Consumers may refine payloads additively with the owning Story while preserving fixed business meaning and acceptance.

Commands carry scoped `commandId` and expected versions. Same identity/input replays the original receipt; changed canonical input conflicts. JSON outcomes distinguish confirmed success, pending/uncertain operation, invalid input, unauthenticated, forbidden, not found, stale/conflict, unsupported capability, unavailable/retryable and internal failure. Their HTTP mapping is 200/202/400/401/403/404/409/422/503/500 in the contract. Errors retain stable codes, relevant version/action hints and durable operation identity without leaking other accounts or upstream secrets. Transport retry and authentication renewal do not authorise resubmission of business intent.

## Persistence and background execution

Use an isolated fresh Java schema with environment/run-scoped mutable state and durable command/event/job identities. SQL reads select affected aggregates; small commands must not default to whole-run hydrate/fingerprint/diff. Optimistic versions and database uniqueness protect active car and employee/entitlement custody. A transaction atomically commits domain changes, command receipt, event/outbox intent and monotonic run revision. Rollback, failed versions, no-op and replay must not invent mutations.

Persist intent before remote I/O, execute outside the SQL transaction, then compare-and-set finalisation. A timeout, malformed/mismatched acknowledgement or uncertain commit remains pending; retain custody and reconcile by the same operation identity. Distinguish the original command receipt from later durable operation status. Independent instances must see authoritative freshness; a cache/projection cannot hide a competing write. Reset retires one run and activates another atomically; late old-run work cannot mutate new-run authority.

This meets the [FUCQ-408 alignment](../gcsp/database-refactor-migration-alignment-2026-11-13.md): bounded selected trigger/receipt reads (419→420), transactional freshness (421), explicit changed identities/write sets (422→423, both→424), and bounded immutable-evidence batching (425). Calculation Stories 409–418 preserve exact identity, all hard gates, deterministic ties, historical explanation and fallback. The entire Node refactor is not a migration gate; all 17 native Node acceptance contracts and claims still stand. Java design is not evidence that their Node changes passed.

`server/index.js` and the inventory identify clock consumers in release, manual expiry, Buddy expiry, pending reconciliation, Buddy allocation and outbox stages, ordered by stable handler ID within each stage. Startup runs expiry/reconciliation only. No unattended runner is introduced. Java ports these semantics and comparison runtime jobs; retained offline trainers/generators may remain JavaScript. Comparison workloads retain 1,000 employees, three declared seeds, 90-day horizon and supported experiments; historical Node memory/time measurements do not establish Java/Render capacity.

Retain immutable source corpus, policy/reference versions, reusable trained model and agreed baseline comparisons. Legacy sessions, scenario/employee operational state, active offers/orders, old links and operational learning/comparison history may reset only at the agreed switch. Replacement state and new links survive ordinary compatible deploys/restarts. Native PostgreSQL commit/rollback, concurrency, uniqueness, replay, uncertain commit/restart and reset isolation remain acceptance evidence; mocks and source inspection do not substitute for them.
