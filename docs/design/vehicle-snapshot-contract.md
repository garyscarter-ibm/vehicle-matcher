# Vehicle facts and scenario terms — FUCQ-26

The additive ES-module contract lives in `server/vehicles/index.js`. It implements the facts/terms boundary agreed in the [shared recommendation design](../gcsp/shared-recommendation-design.md). Existing `mapping.js`, `stock.js`, ranker exports, cache objects and public retail payloads retain their current interfaces. This is an internal contract; no employee HTTP endpoint or allocation behavior is added.

`createVehicleSnapshot(input)` validates, copies and recursively freezes a `vehicle-snapshot-v1` source record. It requires a source namespace, original source keys, identity kind, observation timestamp, snapshot version, display name and facts. Candidate keys encode namespace, identity kind and original candidate ID. Advert, exact stock, VIN and unverified legacy record identities are distinct; model groups cannot be candidate identities. Supplied VINs are format-checked and retained; the contract neither creates nor authenticates them. Refresh/enrichment publishes a new snapshot/version.

Each fact contains `status: known|unknown`, `value` (null for unknown), `unit` (null for non-measured values) and `provenance: { sourceRef, observedAt, version, assurance }`. Assurance is `unknown`, `confirmed-listing`, `confirmed-build`, `model-reference`, `derived` or `synthetic-scenario`. Numeric facts need units; named scored facts validate canonical units and numeric types. Front and rear ISOFIX remain separate boolean/unknown observations. The contract records evidence; it does not decide whether that evidence satisfies an employee essential.

`createRetailTerms` describes a GBP purchase price or explicit null. Zero is distinct from unknown. `createEmployeeTerms` describes points, supplied allowance inputs, a separate cash contribution (amount/currency/period or null), quote version and an exclusive validity end after its start. Supported contribution periods are `month`, `year` and `one-off`. These are representations, without tax, conversion or policy calculations. Quote/policy adapters supply the values and authoritative policy versions; active scheme assumptions must come through `PolicyService` in `server/gcsp/policy/index.js` and its canonical source.

`createEmployeeProjection(snapshot, context)` validates and freezes separate employee key, policy version, evaluation time, quote, eligibility, and optional scores/hold/offer references. It defensively copies supplied data, including source snapshots; changing one employee's supplied context cannot affect another evaluation. Employee overlays are prohibited at the snapshot's top level. The application must supply authenticated context; this constructor grants no access and performs no hold/offer transitions.

`server/adapters/retail-vehicle.js` provides an explicit opt-in boundary:

- `adaptRawRetailVehicle(raw, brand, context)` calls the unchanged `mapVehicle` and records `mapped-now`. A raw candidate requires an advert ID or supplied VIN; a mapper's fallback title/price string is not promoted to a source identity. Missing retail cash price preserves the mapper's existing null result.
- `adaptMappedRetailVehicle(car, context)` records `already-mapped` and a `legacy-record` identity. Its timestamp dates this snapshot, rather than claiming a fresh source fetch/remap. Caller-supplied `modelGroupId` and `stockId` retain their separate meanings.
- `projectRetailVehicle(adapted)` returns a fresh mutable copy of the exact original mapped shape. Metadata stays outside retail payloads. Existing colour enrichment may mutate this copy without changing the immutable adapter input.

Both adapters require explicit `sourceNamespace`, `sourceRef`, `observedAt` and `snapshotVersion` context. Model defaults stay `model-reference`; parsed equipment stays `derived`. Already-mapped listing-shaped values have `derived` assurance because their raw evidence is unavailable. Generic parsed ISOFIX never becomes confirmed front/rear equipment. `monthlyFrom` text is retained only in the compatibility copy and never becomes employee finance. A scheme candidate can be constructed/projected without invoking the retail mapper or providing a retail price.

`server/adapters/synthetic-vehicle-fixtures.js` supplies two tiny immutable fictional stock observations. They have explicit synthetic assurance, no VINs, no policy defaults, no finance quote and no predetermined employee winner. Quote amounts in contract tests are explicit alternative test inputs, not active scheme defaults.

Validation selects the new contract tests for identity, facts, units, isolation, no-price inventory and retail projections; the existing offline compatibility matrix protects public outputs across brands and modes. The story explicitly requires a final `npm test` after equipment integration. No screen or user interaction changes, so payload parity is the presentation contract gate under the [experience contract](../gcsp/experience-quality.md); new screenshots are unnecessary. The affected-test selector supports Python only here, so explicit Node commands and a reviewed boundary map replace uncertain automatic selection.
