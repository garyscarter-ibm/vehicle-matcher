Story DEV-2026-11-09-GC-029. Reviewer: UI and UX SME agent (opus). Judged against `docs/gcsp/README.md`,
`demo-brief.md`, `experience-quality.md`, `build-rules.md`, `COMPONENTS.md` and the run sheet

## Run 1: presenter controls and Paula

Scope: the presenter controls and entry page; Paula's employee journey (sign-in, Your cars, manual selection,
review, order, Resume); her car brief and buddy activity on the way to the offer; the offer and decision
(decline for Body style, change to Saloon, Tick, accept the second offer). Greg, the outbox, order progress
and help are run 2, below.

### Method

- Offline host (`GCSP_OFFLINE=1`, memory repository, ports 9290 to 9297), Chrome headless through Playwright,
  driven by `docs/gcsp/evidence/fucq-248/walk.mjs` (harness and checks) and `sections.mjs` (journeys):
  `WALK_SECTION=presenter|manual|offer|decision WALK_W=1280|375 WALK_PORT=… WALK_SCRATCH=… node walk.mjs`.
  States were reached with the presenter controls as the run sheet does: Reset (Decline then change, Main
  successful journey), Switch principal, Next release, Tick.
- The manual journey was walked in the scenario the host opens with (Clock/reset mechanics), as the FUCQ-70
  walkthrough does, because in Main successful journey the buddy's hold blocks every manual reservation
  (finding 10).
- Every screen at 1280x900 and 375x812, plus a 320 px reflow check on each. Screenshots are
  `docs/gcsp/evidence/fucq-248/<journey>-<width>-<nn>-<state>.png` (numbers run across one walk, so gaps
  between journeys are expected).
- Keyboard: a Tab walk on every screen records each focus stop, whether it shows a focus indicator and where
  focus sits after each action. Actions were taken by focusing the control and pressing Enter or Space.
- No automated checker (axe) is available offline, so the checks are scripted in `walk.mjs`: accessible
  names of focusable controls, target size (WCAG 2.5.8, 24 px; under 44 px counted), text contrast from
  computed colours against the nearest opaque background, horizontal overflow, heading outline, landmarks,
  live regions, images without `alt`, and em dashes in visible text. The screen reader check reads
  Playwright's ARIA snapshot (the accessibility tree) of each screen.

Scripted results that passed everywhere in run 1: every focusable control has an accessible name; no image
lacks `alt`; no text contrast failure in a settled state; no em dash on screen; no horizontal scroll at 375 or
320; no keyboard trap; every target is at least 24 px. Under 44 px (advisory, not AA): 11 controls on the car
brief, the "Car facts" toggles in the gallery, one control on setup and review.
