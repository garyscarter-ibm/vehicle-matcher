Actual FUCQ-69 browse-to-review, frozen FUCQ-66 service composition, FUCQ-71 submission freeze/readback, native PostgreSQL, browser/desktop/320px/keyboard and the authored full suite remain outstanding. ## Components and entry points

`mountManualReview(root, options)` owns one employee shell. `mountManualReviewBody(main, options)` embeds the form in an existing shell. Both return a teardown function exposing `.controller`, `.refresh()`, `.handoff(detail)` and `.leave(reason)`. `defineGcspManualReview(registry)` registers `<gcsp-manual-review>` repeatably; supply its `.adapter` property before connecting it. Its optional `.loadAccount` function supplies the existing shell account projection. The shell mount otherwise uses the existing authenticated account adapter. Load the `manual-review.css` stylesheet; it imports the existing employee and form styles. All JavaScript is external ES modules; there are no inline handlers, scripts or dynamic code execution.

Component plan: reuse `portalShell` through `mountEmployee`, `matchCard`, `screenIntro`, `button`, `statusScreen`, `factList`, `labelledField` and `errorSummary`. The exact quote provides the card's facts, eligibility, typed monthly points and image; its seven-digit order number stays visible. Representative images and missing facts retain explicit labels. The original quote is not repriced from later stock or gallery state. The old contract/slot, returning car, requested collection and pinned contract term stay visible. No shared primitive is added. Native form controls remain mounted through edits, failures and clock refresh. `manual-review.css` is page composition, with semantic shared tokens, a one-column narrow layout and a dedicated ratchet cap. The reference remains `a7fc178` / `evidence/fucq-6/representative-desktop.png`, with supplied screenshots 00/01/05 for shell and information evidence. Rendered visual comparison is not yet claimed.

Options include `adapter`, `commandId`, `handoff`, `loadAccount` (shell only), `subscribeClock`, `onContinue`, `onReleased` and `onBrowse`. `subscribeClock(refresh)` connects the host's presenter-clock notification to an authoritative GET and returns an unsubscribe function. The host also calls `.refresh()` after reconnect/navigation. This module does not infer presenter time from elapsed browser time, install a timer, advance the clock or extend a reservation. The numeric readout is outside live regions. A low-time announcement occurs once per hold/phase, at one-quarter of its supplied phase duration; expiry is announced once. The fraction is a presentation threshold, not a policy duration. Pending or locked holds never announce that the car is free merely because its original deadline passed.

The server remains responsible for eligibility and exact conditional authority.

## Navigation and submission edge

`onContinue({binding,reviewDetailsVersion,snapshot,details})` and bubbling/composed `gcsp:manual-review-ready` represent the same confirmed transition. The host consumes one notification form. They are not an order submission. FUCQ-71 must compare/freeze the emitted exact revision in its existing selection-intent transaction and consume the frozen snapshot for order readback/print. Pending selection never unlocks the metadata. This integration remains unproved.

Back/change/cancel call `release('back'|'change'|'cancel')` independently of form validity. No navigation callback is emitted until a fresh authoritative read confirms a terminal release/expiry/failure. `release()` without a reason retries an existing unresolved release. `onReleased({reason,claim,holdId})` and `gcsp:manual-review-released` are equivalent notifications; the host consumes one. Shell navigation also uses release-first. `.leave()` lets an embedding host apply that same rule before changing its route. Disconnect/destroy only tears down the view and invalidates late callbacks; it does not silently release or reacquire a car. Back/Forward or reopening must mount and read current authority.

An authoritative terminal/expired read offers `onBrowse()` / `gcsp:manual-review-browse` to refresh stock. Pending/uncertain holds past their original deadline do not offer this navigation. Recovery checks current status and preserves safe inputs. A new car needs a fresh gallery read and a separate explicit FUCQ-69 claim.
