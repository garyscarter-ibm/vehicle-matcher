# FUCQ-69 browser qualification plan · 5 November 2026

This plan requires the dispatcher's explicit browser lane grant. No grant or browser result is recorded here. The fixtures qualify presentation only: `gcsp-manual-gallery.html?fixture=available` and the six named recovery fixtures are synthetic, dated, read-only adapters. Review is disabled; they do not prove FUCQ-92 release history, service identity, a live claim or FUCQ-70 integration.

Run the committed `browser-supervisor.py` once per width, first 1280 then 320, with the exact dispatcher grant reference. Freeze consumed source for each chunk; record HEAD, helper/product/source hashes, command and grant in the external plan/receipt. Reuse a successful unchanged chunk; diagnose a failure before selecting an affected rerun. Browser keyboard failures must be separated from native-select harness behaviour before calling them product defects.

The runner uses the existing bundled `playwright-core` and system Google Chrome without installation. It serves only the gallery HTML, required GCSP/shared-kit modules/styles/fonts and the representative BMW image from an owned ephemeral loopback HTTP server. External requests are blocked, CSP is strict, no API is served and Chrome uses its owned pipe without a CDP listener. The fixture adapter cannot claim. The user's foreground browser is untouched.

Each width checks labelled search/series/body/sort controls; keyboard navigation, filtering and exact detail/back focus; long equipment names and decision-critical facts; absent fit scores; image fallback; empty search; and empty-stock, nothing-released-yet, no-suitable-stock, source-unavailable, context-refresh and car-taken presentation. Capture at most ten PNGs, 12 MiB combined, with hashes and observations. The runner explicitly loads the packaged Density heading face, rejects absent/failed font faces and unexpected HTTP error responses, and freezes both GCSP shell and retail-kit font identities. Agent visual review of desktop and 320px captures against the FUCQ-64/body and shell reference remains mandatory after successful capture.

One worker, at most 120 seconds, requested 2560 MiB recursive RSS (minimum admission 2048 MiB), 128 MiB combined scratch/retained output and 2 MiB logs. HostBudget reserves before allocation. The local browser profile/cache is the active working-set compatibility exception; scratch is removed after owned root/descendant/detached process groups, PID/start identities and open files are verified absent. SIGINT/SIGTERM request cooperative cancellation through the supervisor finalizer; the receipt records cancellation. An uncertain cleanup keeps named scratch/reservation evidence for reconciliation. Every DB URL/PG environment alias is removed.

Ownership/plan/log/receipt live in the shared checkout `.claude/test-runs/fucq69-browser/<width>-<unique>/`, outside scratch. Bounded retained PNG/JSON evidence lives under this directory's `browser/<width>-<unique>/`. Receipts verify source identity, scratch/profile/process groups/reservation and HTTP listener absence. No browser is launched by syntax checks; those checks are recorded separately in `.claude/test-runs/fucq69-browser-helper-syntax/receipt.json`.

The authored serial full suite, real released-pool producer and browse→claim→FUCQ-70 integration remain separate outstanding gates. Native database, release commands and runtime registration require their existing owner lanes; this plan grants none of them.
