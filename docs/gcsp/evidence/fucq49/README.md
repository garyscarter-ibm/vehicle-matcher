# FUCQ-49 live named-image boundary

5 November 2026. This is an isolated C14 provider in the existing Node backend. It adds no startup registration, HTTP endpoint, screen, catalogue dependency, retail image change or runtime dependency. The existing snapshot adapter remains the default.

## Source gate and actual qualification

The [pre-implementation source gate](source-gate.md) records Gary’s approved public UK configurator source, image display/retention and bounded engineering plan. This is an unsupported public website demo route; approval does not establish a BMW-supported API or reliability.

The [initial native qualification](native-qualification-2026-11-05.json) used three GETs: current configurator page, its discovered settings and the exact COSY manifest all returned 200. The manifest supplies the collection, viewport dimensions, parent named-image group and child image/distinction records. It supplies **no resolved model, paint, date or option identity**. The first local selector did not correctly join parent names to child images, so it fetched no image. This is not evidence that HEROFRONT was absent.

The corrected selector passed its local positive/wrong-viewport/duplicate smoke. The [separate bounded follow-up](native-followup-2026-11-05.json) then stopped after one GET returned 404 for historical `settings.ae894fd5.json`. That filename came from the 1 November evidence, not the current settings reference discovered in the initial run. Its failure says nothing about the availability of the current source. No retry, page rediscovery, manifest replay or image request followed. Across both native runs there were four requests and no image downloads. First-run success and stopped follow-up remain separate evidence.

**Technical acceptance gap:** no approved source evidence currently establishes the complete independently resolved configuration/date/options for these live named assets; no native named-asset bytes were retrieved. Therefore actual COSY input fails closed with `identity-unverified` and no image. Neither sending a complete option list nor matching an image’s known model/paint can establish every option/date. Injected positive tests are contract tests and do not close this live proof gap.

## Explicit backend composition

Import `createBmwLiveImageryProvider`, `bmwLiveImageLookupIdentity` and `presentBmwLiveImage` from `server/vehicle-evidence/bmw-live-imagery.js`.

The factory requires `environment: 'gcsp-demo'`, `sourceProfile: 'bmw-uk-public-configurator'`, an injected bounded `transport` and backend-only `getCredential(profile)`. A deployment may obtain the key from a backend environment secret or approved public-settings handling; this module discovers no key, reads no environment variable and makes no default network request. Keep public application credentials solely in process memory. Missing selection/credentials returns unavailable.

`resolve(request)` takes the same complete known snapshot fields as the offline adapter, plus explicit `viewport`, `namedImage` and `distinctions`. For the observed reference these are `desktop`, `Gallery`, `HEROFRONT`, dimensions 2560 × 1646 and `{ BKGND: 'sand', X: '1700', Y: '500' }`. `selectionComplete: true`, every exact date/model/AG field, sorted canonical options and accessory quantities remain part of the lookup identity. Paint or a broad model name alone is insufficient. Missing view/size is unsupported; ambiguous/malformed records are unavailable. No crop/size is manufactured and the entry count implies no 360-degree viewer.

The optional trusted backend dependency `resolveConfiguration({ manifest, requestedIdentity, signal })` represents **independent source evidence**, not an upstream COSY field or browser assertion. Its result must have `basis: 'independent-source-proof'`, a complete `identity` including `selectionComplete: true`, and valid `observedDate`; `fidelity.model` and `fidelity.paint` may independently be verified or unknown. The provider canonicalises and compares every model/date/option/accessory before fetching an asset. Missing proof is unavailable; mismatches are explicit. No implementation of this independent proof is supplied or established by the native qualification. Do not create a callback that merely returns the request or pretends an unobserved manifest field exists.

The transport receives `{ method, url, headers, signal, maxResponseBytes, credentials: 'omit', cache: 'no-store', redirect: 'error', retries: 0 }` and returns `{ status, contentType, body }`, optionally exact final `url`/`redirected`. It must enforce the stream cap and AbortSignal while reading. Source URLs stay inside this backend dependency. One operation per provider, one manifest ≤1 MiB, one image ≤2 MiB, zero retries and a total deadline ≤15 seconds are enforced. The selected collection/origin and exact `connext-bmw/cosySec` asset path are fixed; no caller URL or alternate-origin proxy is accepted. Returned asset URL bytes are used unchanged, with no manifest credential sent to the image and no assumed expiry.

Only validated static WebP bytes with the selected declared/encoded dimensions enter the four-entry memory registry. `resolve` returns an opaque server asset ID; `readAsset(assetId)` reads only registered bytes and cannot fetch a URL. Call `dispose()` during composition teardown to abort owned transport and clear memory artifacts. No signed URL, credential or raw upstream error appears in an envelope or safe presentation projection. Nothing is silently replaced with a snapshot; a caller can separately choose the existing snapshot adapter with its own provenance.
