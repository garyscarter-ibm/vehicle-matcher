## Diagnosis
- **FUCQ-518.** Reproduction: FUCQ-435 cross-origin proof scenario c (`docs/gcsp/evidence/fucq435/2026-11-17/cross-origin-proof.json`,
  product defect `claim-hold-mode-local-rejected`). Cause, confirmed against Node: `ClaimRow.hold()` emitted `mode` from
  `manual_claims.mode`, which is the claim adapter (`local`/`remote`, `ManualClaims.java:498`). Angular's `manualSelection()`
  (`apps/gcsp-web/src/app/manual/manual.projection.ts:16`), `isManualReviewDetails()` (`v.mode === h.mode`) and
  `manualDetailsMatchClaim()` need the journey mode `new`/`replacement`. Node's adapter mode is never `hold.mode`; the journey
  is the pinned draft's `choices.mode` (`server/gcsp/manual-review/index.js:71,102`). Angular is right, Java diverged.
  Readers affected: GET/POST `manual/claim`, `manual/quote`, `manual/claim/review`, `manual/claim/release`, `manual/review-details`
  (its `hold`). Not affected: `ClaimView.mode` for ordering (still the adapter mode), `manual_claims.mode` column. No stored data changes.
- **FUCQ-519.** Reproduction: proof scenario i (`offer-read-sends-runId-query`). Cause, confirmed: Angular sends `?runId=<context.runId>`
  on `GET offers/{id}` and `GET offers/{id}/decision-reasons` (`offer.client.ts:74,81`); Java `OffersResource` refused every query
  with 400. Node accepts one optional `runId` on the read and exactly one on decision-reasons, refuses any other key, and answers
  a non-current run `stale-run` (`access-http.js:68`, `decision-http.js:67`, `access.js:175,266`). Java diverged.

## Fix
- `services/gcsp-api/src/main/java/gcsp/api/claims/ClaimRow.java`: LEFT JOIN `manual_drafts` by primary key on the quote's pinned
  `draft_version`; `hold.mode` = the draft's `choices.mode` (null if no pinned draft). One extra PK lookup per claim read, no new query.
- `services/gcsp-api/src/main/java/gcsp/api/offers/OffersResource.java`: `runSelector` on the offer read and decision-reasons only.
  No query or one `runId` equal to the caller's active run proceeds; another run 409 `stale-run` (`offer-from-earlier-run`);
  blank or over 128 characters 400 `invalid-offer-selector`; any other key or a repeated `runId` 400 `unsupported-query`.
  `/current`, POST `/decision` and `/follow-up` still refuse any query (Node does the same).
