# FUCQ-78 offline stock generator checkpoint

6 November 2026. This is an independently executable implementation checkpoint, not story acceptance or a published demo stock set. No real stock-locator request has run. The F77 accepted demo plan and at least 200 constructible real configurations remain unavailable; the two-configuration lookup reference and three historical qualified observations do not satisfy that coverage.

`createStockGenerator` in `server/gcsp/vehicle-evidence/stock-generator.js` accepts the existing TransactionRepository, immutable registry, canonical PolicyService, trusted `contextForRun`, explicit configuration plan, stock account and absolute trusted `allocationInventoryPath` for F53's whole retained identity inventory. It returns `generateStock(runId, seed, policyVersion)`, for future F85 composition. It has no reset, release, transport, price, eligibility, hold, offer or claim operation. Runtime composition remains a separate coordinated gate.

The configuration plan binds exact existing `configurationId` values to model-line and colour labels. Its dataset/version must match every registry read from the same selected manifest. Labels never create configuration identity. `kind: synthetic-fixture` remains visible in every fixture report. An `accepted-f77` binding additionally requires aggregate policy rows with status `observed aggregate` and value source kind `observed-aggregate`; an accepted-plan label cannot promote assumed fixtures. The trusted producer still needs the actual accepted F77 artifact. The sampler's proposed acceptance envelope is an adapter proposal, pending that artifact.

The generator uses F53's existing `readAllocationInventory` and `allocateInventoryFile` boundary for UUID-v4 order keys, seven-digit order references and eight-digit wholesaler references. It supplies the whole retained inventory, including other runs, with the existing exclusive allocation lock and revision check, so finite-space collisions cannot be hidden by a fresh inventory. Stock contains no VIN. Allocation reservation and repository publication are two separate stages, not one cross-resource transaction. A failed stock write leaves valid F53 reservations retained; the same request reuses them on retry. The generator binds its `stock-` vehicle namespace to the request digest and rejects changed seed/plan/account/source bindings before adding reservations. Other F53 vehicle namespaces can coexist in that inventory. It writes all cars and the report in one F81 transaction, as `state/status: unreleased`, `available: false`, with a stock account, planned release window, synthetic identity and confirmed delivery week. The release window has `at`, `windowStart` and exclusive `windowEnd` at the following cadence slot. It grants no availability or visibility; F92 owns release. Delivery weeks use the release's local calendar and observed per-model lead time. The observed delivery-date spread and cash price band remain report evidence, not points prices or eligibility.

The same run, seed, pinned policy, immutable configurations and plan yield the same stock. Hamilton apportionment bounds model/colour rounding rather than relying on chance at demonstration sizes. Policy cadence supplies weekday/time/time zone; no consumer weekday default replaces it. Replaying the same run/seed/policy/plan/account/clock request returns the persisted original report before allocating or writing. The request digest is retained in the run generation metadata. Changing an input for an already generated run conflicts before allocation; F53's immutable associations are preserved. Reset creates a new run rather than replacing an existing run's identities. Other runs and the corpus remain unchanged. Native PostgreSQL persistence and F85/F92 invocation have not been proved here.
