## Provider-specific freshness and retention

The observed manifest supplies no supported asset expiry or currentness guarantee. The provider therefore revalidates the manifest, independent complete configuration and returned image **on every `resolve`**. There is no manifest/result cache hit, conditional reuse or shared cache TTL. `cache: no-store` and zero automatic retries remain mandatory. The complete canonical lookup includes provider/schema/manifest version, market/locale, model/range/AG/trim, every catalogue/order/effect/production/tax date, complete sorted options and accessories, viewpoint, viewport, named image, dimensions and distinctions. The opaque handle also includes the content hash and resolution generation, so a later resolve cannot refresh an earlier handle.

The memory registry is delivery custody, limited to one validated image of at most 2 MiB. A new admitted resolution clears the previous handle even when the new attempt fails. `readAsset` consumes the handle once; an unused handle stops being deliverable after a **local 15-second handoff window**. Invalid or backward clocks fail closed. This bounds the application's handoff, not BMW's asset lifetime: `freshness.status` remains `unknown` and `upstreamExpiresAt` remains `null`. Expired, consumed and disposed handles do not fetch anything. `dispose()` aborts owned work and clears bytes.

Repeated browser reads require a new `resolve`, yielding a new handle and making another bounded source request. A later HTTP/UI consumer must account for this explicitly and send no-store delivery responses; it cannot treat this handle as a permanent `<img>` URL or automatically loop on failures. This story adds no HTTP image route or consuming screen. Existing C14 snapshot delivery remains suitable for repeatable offline imagery. The source permission allows longer retention, but this live runtime deliberately chooses no cross-resolution reuse while upstream freshness is unknown.

## Safe failures and exact delivery

Each resolution makes at most one manifest and one asset request under the existing total deadline of at most 15 seconds, concurrency one, 1 MiB manifest and 2 MiB image caps. There are **zero automatic retries**, including for authentication failures. `401`/`403` return non-retryable `access-denied`; `429` returns `rate-limited` with an optional safe `retryAfterSeconds`. Delta-seconds and canonical HTTP-date hints are accepted only within one hour; invalid, secret-bearing or longer hints become `null`. The hint advises a deliberate later attempt and never schedules one. Other HTTP/server failures, timeouts, malformed manifests, missing views and broken/expired asset responses yield finite unavailable/unsupported outcomes.

The fixed HTTPS COSY origin, exact collection and `connext-bmw/cosySec` path, unchanged opaque returned URL, rejected redirects, JSON/WebP content types, encoded static WebP dimensions and response caps remain enforced. The manifest credential is never sent to the asset. No caller URL, generic proxy, transform or 360 viewer is introduced. Transport dependencies must enforce response streaming caps and aborts and must not log credentials or private source URLs. This module emits no source logs and projects only fixed safe messages, dates, fidelity and registered opaque IDs; upstream bodies, raw exceptions, headers and URLs are never retained in an envelope or presentation.

## Explicit C14 snapshot selection and presentation

`selectBmwImageSnapshot(request, { environment: 'gcsp-demo', assetId })` is a separate intentional action. It resolves the complete requested identity through the existing C14 adapter and accepts only the explicitly selected white or black registered asset. A wrong model, paint, date, view/size or asset choice stays unavailable. No live failure calls this function, and generic/model-mismatched fallback is excluded here. Successful snapshot selection preserves its own provider, source, observation/retrieval dates and fidelity. It does not inherit the live label or live retrieval date, and does not resolve a different requested car.

`presentBmwLiveImage` covers unavailable imagery, “Representative image” with **current source freshness unknown**, and an explicitly selected “Snapshot image” with dated snapshot provenance.
