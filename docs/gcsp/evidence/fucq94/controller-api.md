# Initial brief controller API

5 November 2026. This is a DOM-free initial checkpoint of FUCQ-94, not the completed screen or story.

`createBriefController({ context, initial, transport, createCommandId, onChange })` is exported from `blocks/gcsp/brief/brief-controller.js`. All ports are required except `initial` and `onChange`. The controller owns no browser storage, policy defaults, endpoint URL or scoring rules.

`context` is a trusted server-owned editor projection. It supplies `slider: { minimum, maximum }`, registered `preferences` and `essentials`, optional sourced `knownFacts` and optional fact `permissions`. Each preference definition declares `type: slider|enum`, enum `values` where applicable, and explicit `editable: true` to allow changes. Each essential declares `type: number|boolean|string|list|enum`, `operator`, `unit`, optional enum `values`, numeric `minimum`/`maximum`/`integer`, and explicit `editable`. Canonical registry definitions and bounds come from PolicyService through the supporting editor adapter. These are presentation definitions, not a new browser registry. Known facts and their permission metadata are exposed for presentation only; this slice has no known-fact write API.

`initial` accepts only `{ brief, briefVersion, draftVersion, consent }`. Both versions default to zero; consent defaults independently to `{ search: false, hold: false }`. Pass explicit saved consent from a trusted current-state projection when available. `brief` accepts the FUCQ-91 editable schema `{ schemaVersion: 1, preferences, essentials, currentCarFeedback? }`; defaults are empty maps, never invented weights. Approved/read responses must be projected to these editable fields before construction; authority fields are rejected. Known facts come separately from context.

Public operations:

- `snapshot()` returns a detached snapshot including editable brief, versions, known facts, permissions, consent, dirty flag, preview and save state.
- `subscribe(listener)` adds a state listener and returns its unsubscribe function. `onChange` is an initial listener. Each listener receives its own detached snapshot; observer exceptions cannot interrupt state transitions.
- `updatePreference(key, { value?, importance? })` changes registered editable fields independently. A missing preference needs both fields on its first edit. Minimum importance preserves position. Employee edits set the affected state to `draft`, use source `employee` and remove the shared stale `confirmedAt`.
- `updateEssential(key, value)` uses the registered operator/unit and typed value. Null means `needs-confirmation`; false, zero and an empty equipment list remain explicit employee draft answers. No yes/no-to-numeric/list conversion is invented: the editor's canonical practical mapping supplies it. Edits remove old confirmation metadata.
- `setConsent({ search, hold })` requires both explicit booleans, independently. It changes no preview or durable permission.
- `requestPreview()` sets loading immediately and schedules through the existing `createPreviewFeed`. Relevant brief edits also schedule. `cancelPreview()` returns to idle and invalidates pending work.
- `save()` captures one complete draft/consent snapshot, writes it and then confirms its actual returned draft version. Repeated calls while saving return `busy`. Each phase gets a separate stable ID from `createCommandId('draft'|'confirm')`. No automatic retry is performed. If a saving-state observer tears the controller down, no draft request starts.
- `destroy()` cancels the shared feed, clears subscriptions and blocks new edits/requests and late result delivery. A dispatched transport is not physically aborted; a late draft cannot trigger confirmation after teardown.

Consent accessors are rejected without execution. Invalid edits return `{ status: invalid, field }` without changing state. Successful edit/schedule operations return `{ status: ok }`. After teardown these operations and save return `{ status: destroyed }`. Initial invalid schema/context throws `TypeError`. Caller inputs, snapshots, listener state, outgoing requests, received outcomes and returned save outcomes are detached. Prototype/unknown fields and identity/run/policy/fact/cash/contribution writes fail closed.

## Transport boundary

`transport.preview(snapshot)` receives `{ kind: unsaved-draft, baseBriefVersion, draftVersion, brief }`. It receives the complete editable draft, including charging, with no known facts or claimed approved `briefVersion`. There is deliberately no default browser HTTP implementation. The existing FUCQ-29 route requires a positive approved version, confirmed input and no charging essential. The supporting guarded `POST /api/gcsp/brief/preview` adapter validates unsaved intent and its current base/draft versions before invoking the real shared evaluator, retaining explicit unapproved provenance; this controller neither erases charging nor pretends an unsaved brief is approved.

Preview responses use the real FUCQ-29-shaped `{ status, value?, contractVersion? }` envelope. Successful value has `state: recommendations|no-stock|no-viable-stock`, `recommendations`, complete `decisions`, `eligibleCount` and `versions`. The controller preserves complete supplied outcomes, grounded reasons, trade-offs, decisions and versions. State is `recommendations` when recommendations exist, `essential-unknown` when none exist and a candidate needs confirmation, otherwise `zero-eligible`. Malformed/missing successes and typed/source failures yield `unavailable`; failures retain their typed outcome. Recommendations coexist with unknown candidates. The shared feed owns debounce and immediately invalidates stale success/failure callbacks on schedule/cancel.

`transport.saveDraft(command)` receives `{ commandId, expectedBriefVersion, expectedDraftVersion, brief }`. Its successful FUCQ-91 envelope supplies `value.draftVersion` and matching `value.baseBriefVersion`. Only success triggers `transport.confirm({ commandId, expectedBriefVersion, expectedDraftVersion: returnedDraftVersion, consent: { search, hold } })`. Its successful envelope supplies `value.brief.briefVersion`; the complete outcome remains available under `snapshot().save.outcome`.

Save state is `idle`, `saving`, `saved`, `failed` or `refresh-required`. Typed invalid/forbidden/stale-run/unavailable failures remain typed outcomes. Conflict/stale-version requires explicit refresh/review and preserves the complete current edits and base versions without retry. A non-conflict confirmation failure retains the already saved draft version for the next explicit operation. Success advances actual approved/draft versions while retaining edits and consent made during the request; those edits remain dirty. Saving grants neither consent by inference.

## Scoped evidence and remaining work

It uses recorded FUCQ-91 fixtures and FUCQ-29 computed evidence. The FUCQ-29 evidence record summarises recommendations as IDs; the test restores full decision entries to match the current producer's response shape. This is controller boundary coverage, not a new live service execution.
