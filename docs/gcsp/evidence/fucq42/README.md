# FUCQ-42 offline image selection

5 November 2026. The existing image port reuses FUCQ-37's canonical catalogue identity and FUCQ-40/41's registered assets and fidelity contract. This change shares the registered type/dimensions/reference check with `presentBmwImage`: an inconsistent projection now reports unavailable instead of exposing an asset ID. No provider, identity module, runtime wiring, screen or asset was added.

## Usage

Trusted demo composition imports `createBmwImageAdapter`, `bmwImageLookupIdentity` and `presentBmwImage` from `server/vehicle-evidence/bmw-image-adapter.js` and explicitly constructs `createBmwImageAdapter({ environment: 'gcsp-demo' })`.

Supply the complete resolved catalogue identity with `selectionComplete: true`, `viewpoint: 'HEROFRONT'` and `size: { width: 2560, height: 1646 }`. `JSON.stringify(bmwImageLookupIdentity(request))` is the canonical request/cache key; this module does not install a cache. It extends the existing catalogue identity with the image provider/version, manifest version, viewpoint and size. Options and accessories are canonicalised by FUCQ-37. Changing market, locale, either model range, model/AG code, trim, any source date, selection/accessory quantity, provider/schema/manifest version, view or either dimension produces a different key. Request extras and private identifiers are excluded.

Only the registered white and black **HEROFRONT / 2560 × 1646 / image/webp** artifacts are supported. Their lengths, SHA-256, WebP signature and encoded dimensions are checked before delivery. Unknown or duplicate references and missing/inconsistent metadata fail unavailable. Unsupported views/sizes are explicit; there is no resize, crop, URL edit or invented expiry. The research's 39 desktop entries include crop variants and establish no 360-degree capability.

[Recorded contract examples](presentation-examples.json) are generated by [the local recipe](record-examples.mjs):

| Example | Observable result |
|---|---|
| White / black observed selection | Distinct representative renders; model and paint verified, equipment/physical-car appearance unknown. |
| Missing local bytes | `source-unavailable`, `asset-unavailable`, no image or displayed asset ID. |
| SIDELEFT or 1280 × 1152 | `unsupported`, no image; no substitute crop or size. |
| Explicit generic choice for an unsupported configuration | Representative asset with every fidelity field unknown, no resolved configuration and no matching-paint claim. |

The generic choice is `resolve(request, { fallback: 'bmw-i5-generic-20261101-v1' })`; omission preserves the original failure. It cannot bypass environment, identity validation, provider/version or view/size restrictions. `readAsset(assetId)` delivers a validated server-side Buffer; no browser/private/signed URL is constructed. Future consuming UI and delivery remain separate work.
