## Authored protection

The small owned `decision-mixed-lifecycle.py` helper is frozen with the supervisor and auditor before any launch. Importing it has no allocation effects. The supervisor installs Python SIGINT/SIGTERM handlers before allocation that set one cancellation event. It keeps those handlers active through source preparation, spawn, registration, join, scratch teardown, reservation handling and receipt writing. The shared launcher's existing poll loop receives that event. This defers handled cancellation without blocking signals inherited by an exec'ed child; no thread or background worker is added. Preparation observes cancellation before allocation and during source-copy/launch boundaries.

`LaunchOwnership.begin()` persists an explicit creating intent before calling the shared launcher. `OwnedScratch.child()` delegates to registration that first retains the actual Popen handle in memory, then records group/PID/start ownership and persists it. A registration identity/persistence exception therefore leaves an adoptable handle. Both the selected-run finalizer and scratch finalizer call the same stop/join/absence check. A captured handle is stopped/joined even after failed registration; the result must be durably recorded before deletion is permitted.

An attempted launch with no captured handle becomes **unresolved**, even if group/process lists are empty. A persistence failure, sample failure, live recorded descendant or uncertain process-group query also blocks cleanup. Only `group_has_live_members(...) is False` establishes group absence. The scratch finalizer refuses deletion in those cases. The outer finalizer withholds explicit HostBudget release unless child ownership/join, group/process absence and scratch removal are all known. It records named leftovers for root reconciliation. A reservation-release error is retained as uncertainty rather than aborting receipt preparation or claiming release.

Reservation retention means this helper does not explicitly release an unresolved allocation. The shared HostBudget prunes dead-owner entries on later admission, so this owned change cannot promise that an entry stays charged after the supervisor exits. The summary records that limitation; unresolved resources require root reconciliation before further allocation. No shared accounting policy is changed here. Unreadable reservation records also remain unknown rather than being treated as an empty registry. Independent child ownership/join and scratch absence are mandatory even if an entry was pruned.

The independent post-exit auditor now requires explicit creating/joined evidence: either no attempt with the `not-started` state, or a captured group/PID with `joined:true` and no lifecycle issues. When the scratch manifest remains, its launch/group/process fields must agree with the summary and its state must be removed. Unresolved launch evidence cannot be laundered into a passing audit by vacuous empty-list checks. This audit does not kill unknown children or release uncertain reservations. Existing independent source/dependency identity and resource absence checks remain required.
