# FUCQ-103 browser preparation checkpoint

6 November 2026. Preparation is separate from rendered acceptance. No browser,
full suite, native database, external send or shared-run policy activation is
claimed by this checkpoint.

The executable inputs are `browser-runner.mjs`, `browser-supervisor.py`,
`browser-embed.html`, `browser-embed.mjs` and `browser-source-plan.json` in this
folder. The JSON catalogue records a finite static dependency closure from the
runner and delivered presenter/embedding entrypoints: relative imports/exports,
literal `new URL`, HTML resources and CSS imports/URLs. Installed package files
and executable identities are pinned separately. The catalogue cannot hash
itself; its SHA-256 is recorded in the receipt and dispatcher handoff.

The driver composes the delivered `createGcspRuntime`, real `MemoryPolicyProvider`
with the unmodified canonical seed, `buildServer`, the real Greg adapter and
`createBriefRuntimeAdapter`. The memory store remains observable only to verify
one append on retry. Five explicitly synthetic persisted employee/confirmed-brief
subjects meet the canonical privacy threshold; they are scenario inputs, never
real producer or corpus evidence. The initial quote is calculated through actual
HTTP recommendations and persisted with its occupying hold/active offer. Its
quote, hold and offer rows must remain byte-equivalent throughout publication.

Disposable loopback HTTPS preserves the actual Secure/HttpOnly/SameSite cookie
attributes. OpenSSL, Chrome, its profile, the loopback listener and DevTools port
are owned by the supervisor. Cookie/token values and TLS keys are never retained
in evidence. Ordinary HTTP switch-principal commands select Greg and Paula.
The brief embed uses the actual editor/preview transport rather than the existing
representative fixture harness. All host modules are external and CSP-safe.

Three separately admitted chunks are planned:

- `smoke-desktop`: 1280px presenter/dashboard/custom-element embedding, unique
  instance IDs, disconnect/remount while a real policy request is outstanding,
  and Paula's actual 1100-point brief preview.
- `journey-desktop`: 1280px native points/weight controls, row retention,
  slider/exact-value and keyboard checks, validation-summary links, busy/ready
  states, actual publication, changed demand/fit and employee terms, preserved
  pinned history, stale rejection, non-Greg refusal and original-command retry
  after a deliberately dropped accepted HTTP response.
- `journey-narrow320`: an independent fresh copy of that actual journey at
  320px with captures and document-overflow checks.

Each browser chunk requests 2560MiB RAM with a strict 2048MiB minimum, 120 seconds,
128MiB combined scratch/retained output, 2MiB logs, one worker and one browser.
The supervisor writes an external ownership manifest before disposable allocation,
uses a fresh machine-wide HostBudget reservation, tracks recursive and detached
process identities/ports/profile/open files, joins monitor/readers/processes,
verifies cleanup and removes only owned scratch and inode/target-matched dependency
links. Uncertain roots are preserved with an explicit cleanup issue. Environment
DB aliases, PG variables and Node preload/coverage options are removed without
reading a secret file. Small local scratch is a declared browser IPC/profile
compatibility exception; no large output is planned.

The selected preparation command is
`/usr/bin/python3 -B docs/gcsp/evidence/fucq103/browser-supervisor.py prep`.
It has 120 seconds, 512MiB RAM, 128MiB combined allocation, 2MiB logs and one worker.
It parses the supervisor AST, syntax-checks only the two new MJS modules, validates
finite hashes/static guards, and imports no application runtime. Browser execution
additionally requires the reviewed pushed revision to equal both HEAD and its
configured upstream, an unchanged catalogue and clean executable/assets state.
