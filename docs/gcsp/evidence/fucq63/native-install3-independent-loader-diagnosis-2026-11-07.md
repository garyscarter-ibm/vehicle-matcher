The archive name `ca-certificates--2026-10-20.all.bottle.tar.gz` matches `/opt/homebrew/Library/Homebrew/global.rb:54`. Renaming that valid filename would not address the observed loader route.

The first cause is the installed Homebrew local-package policy. `/opt/homebrew/Library/Homebrew/env_config.rb:1038` defaults `forbid_packages_from_paths?` to true outside tests/developer mode. The install3 child environment supplies none of its opt-outs. `/opt/homebrew/Library/Homebrew/formulary.rb:546` therefore returns from `FromBottleLoader.try_new` before its filename check. The observed `NullLoader` → `core_path` → API stack is consistent with that guard. The Ruby loader recognises `HOMEBREW_INTERNAL_ALLOW_PACKAGES_FROM_PATHS=1`, but placing it only in the child process environment is insufficient: `/opt/homebrew/Library/Homebrew/brew.sh:655` explicitly unsets that variable before dispatching Ruby. This shell startup step was missing from the initial hypothesis. Any diagnostic relying on that internal opt-out must set it inside the already-started Ruby process before invoking the loader; this is a diagnostic design observation, not a successful install or new install grant.

There is a separate cache blocker. `native-install-3-local-archives-2026-11-07/install-local.py` copies only `packages.arm64_golden_gate.jws.json.payload` into its owned cache. `/opt/homebrew/Library/Homebrew/api.rb:457` first requires the nonempty signed `packages.arm64_golden_gate.jws.json` envelope. Its payload sidecar is usable only when envelope size/mtime fingerprint and signature match (`api.rb:489`). Payload alone cannot satisfy this route, so the network-denied subprocess attempts its forbidden API download. Even with local packages allowed, `FromBottleLoader.initialize` still calls `Formulary.path(full_name)` (`formulary.rb:565`), making the API cache requirement independent of the first guard.

The existing shared signed envelope is available read-only at `/Users/usget/Library/Caches/Homebrew/api/internal/packages.arm64_golden_gate.jws.json`: **15,973,185 bytes**, SHA256 **`5ce934895df1f66d1fd42da2e433922560f226c14cae8c36c74427a11fe60b4b`**. JSON parsing found payload and signatures fields with one signature. This investigation did **not** cryptographically verify that signature. With a nonempty envelope and the internal API's default `stale_seconds: nil`, `API.skip_download?` returns true (`api.rb:33`), and `fetch_json_api_file` parses/verifies the cached JWS instead of initiating curl (`api.rb:78`, `:176`). Homebrew can generate its own matching sidecars inside the owned cache. No `.etag` file is required for that no-download branch; copying old sidecars without preserving the envelope mtime would miss their fingerprint optimization.
