## Closed v2 envelope

Add explicit `schemaVersion:"2"`, `providerVersion:"2"`, provider `bmw-catalogue-snapshot`, `sourceKind:"dated-snapshot"` and `sourceContractVersion:"bmw-public-solver-selection.v1"`. Dispatch on this exact tuple; never infer versions from nullable fields. Register immutable v2 snapshots explicitly alongside unchanged v1. The envelope's exact keys are:

`schemaVersion,provider,providerVersion,sourceContractVersion,snapshotVersion,sourceKind,status,observedDate,retrievedDate,requestedIdentity,resolvedIdentity,lookupIdentity,resolvedLookupIdentity,identityProvenance,sourceBinding,facts,equipment,completeness,failure`.

V2's fixed internal registry entries contain `snapshotVersion,path,artifactSha256,bindingDigest,sourceContractVersion`; verify bytes before parsing. Caller identifiers never become filesystem paths. Replacing content requires a new registration, preserving history.

Reuse bounded v1 failure outcomes and five measurement definitions/units. V2 successful `status` is `partial` whenever optional metadata, quantities or measurements are unknown. An entirely unknown measurement set does not invalidate independently proved selection. Failure envelopes contain null resolved identity/binding and unknown facts; they never provide usable selection.

V2 lookup identity has exactly `provider,providerVersion,schemaVersion,sourceContractVersion,snapshotVersion,bindingDigest,configurationId`. All strings use existing bounded version/date/code validators; digest is lowercase SHA-256. `configurationId` uses the existing pinned PolicyService signature and actual VG model plus sorted unique complete factory codes. Accessories, dates and labels do not change it. Retain AG separately; never switch the signature model base.

`bindingDigest = inputDigest(sourceBinding)` using `repository/core.js:22–26`, with normalized sorted sets and evidence entries sorted by unique ID. Lookup/cache equality includes the entire v2 lookup. Requested/resolved identities are the lookup with provider/version keys removed; both and both lookups must equal the independently loaded registered snapshot. A caller-supplied digest never establishes source authority. Null/unknown is an exact state, never a wildcard. Changing unknown to known creates a new binding/snapshot; old associations remain immutable.

`sourceBinding` has exactly `requestScope,confirmedContext,canonicalIdentity,selection,optionalFacts,evidence,producerPins`:

- `requestScope`: exact `market,locale,catalogueRangeKey,requests`. Each request has `operation,method,url,modelCode,orderDate,effectDate,includedCodes,mandatoryCodes,excludedCodes,trimInput`; unused scalar values are null, code sets sorted unique. Keep tree-request effect date separate from returned model effect date. URL `trim=S0337` remains input only.
- `confirmedContext`: evidence-valued `modelCode,agModelCode,rawModelRange,orderDate,effectDate,taxDate,steeringLiteral`. Model/AG/order/effect must be known for this selected contract; tax/steering may be unknown. Catalogue range key, market and locale remain declared request scope unless independently returned. Inconsistent model/date responses reject; intentional tree-query/returned-date differences remain explicit.
- `canonicalIdentity`: exact `vgModelCode,agModelCode,factoryOptionCodes`; VG/AG agree with confirmed model facts.
- `selection`: exact `constructible,factoryComplete,accessoryCodesComplete,elements,factoryOptionCodes,accessories,evidenceRefs,solverChanges`. First three must be true. `elements` is the complete sorted unique `{code,type}` set, with actual `option`/`accessory` source types; its partitions must equal factory/accessory sets. Accessories are unique sorted `{code,type:"accessory",quantity}` records. `solverChanges` contains sorted `added,removed,ignored` codes checked against original requests and actual selected elements.
- `optionalFacts`: exact evidence-valued `trim,catalogueProductionDate,modelName,fuelTypeCode,physicalProductionDate,modelYear,plant,verifiedFitted`. No effect/tax-to-production inference, package-to-trim mapping, BEVE-to-fuel mapping or invented physical fitting.
- `evidence`: bounded unique records containing `id,role,sourceId,sourceVersion,operation,request,responseSha256,retainedSha256,observedAt,retrievedAt,locators`. Role is `model-tree`, `solver` or `definitions`. Request contains safe method/URL only; each locator has `name,sourcePointer,retainedPointer` with raw/retained RFC6901 pointers. Keep response-byte hash distinct from retained-byte hash. Never retain headers/keys or opaque garage/rule identifiers.
- `producerPins`: exact `projectorSha256,qualifierSha256,sessionSha256,policyVersion`. Pin actual loaded producer bytes and the coherent signature-policy version, not a copied implementation.

Every evidence value has exactly `state,value,reason,evidenceRefs`: known requires validated typed value, null reason and nonempty independently qualified references; unknown requires null value, empty references and an allowlisted reason (`absent-evidence`, `unsupported-physical-evidence`, `quantity-not-exposed`). References have exactly `evidenceId,locatorName` and resolve to response-role locators. Positive integer quantities are known only with direct exact-selection evidence. Limits: 256 factory codes, 64 accessories, 16 evidence records; existing code/date/string/JSON-depth/body limits remain. Required fields, duplicates, unexpected keys, invalid references, hashes or mixed versions reject before enrichment.

Envelope observation/retrieval dates derive from the primary solver observation/retrieval, not file-load time. Every supporting artifact keeps its own original timestamps; unavailable retrieval timestamp stays unknown and cannot be invented. Snapshot registration requires proved primary observation/retrieval dates. Older definitions stay dated and may support labels only under reviewed exact context binding; they cannot prove current solver selection. Pin source, projector, qualifier, policy and schema versions in plan/session/cache identity. Changed semantics reject resume; no automatic checkpoint migration.

The four physical/VIN entries remain unknown for this source-contract version. Solver order/effect dates are request scope, not response echoes. The association basis is the exact dated solver URL plus returned tree model/order/effect facts and solver-returned modelCode within the same reviewed source session, with matching source/version and evidence pins. The tree's own query effect date remains separate. This establishes a reviewed cross-operation association, not solver-returned dates; no resolved solver date may be manufactured.

## Completeness and admission

V2 equipment retains existing definitions/availability/verified-fitted distinctions. `selected` has exact `state,options,accessories,factoryComplete,accessoryCodesComplete,accessoryQuantitiesComplete,provenance`; no v1 `complete` alias. V2 completeness uses separate `factorySelection,accessoryCodes,accessoryQuantities,measurements,definitions,availability,verifiedFitted` states. Preserve `SE000001` and unknown quantity; never coerce to one or omit it. Accessory quantity unknown can coexist with complete code sets and canonical constructibility, but cannot support pricing, accessory totals or an exact v1 lookup. Empty accessories are complete only when the complete actual solver response contains none.

Trim, catalogue production date, names/fuel and physical/VIN facts can remain unknown without changing canonical identity. Essential eligibility/profile mappings and scheme coverage still require their own evidence; unknown essentials remain needs-confirmation. F77's 74 mappings, 8/200/592 thresholds and date holds are unchanged.

Admission still requires: a bounded complete solver body proving constructibility/model and every selected source-typed element; exact model/date association with confirmed tree facts; paint/upholstery classification bound to selected codes; source-added/removed/ignored evidence; immutable evidence/registration; and actual F59→F60→F54→application validation. Current tree/options bootstrap and 15 qualified fields supply no solver-completeness proof. Earlier safe solver evidence is historical candidate evidence, never automatically relabelled or admitted. Design/fixtures keep `accepted=[]`, admission false.
