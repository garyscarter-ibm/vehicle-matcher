# Collector and shared session contract

No default network provider is installed. Importing the modules performs no collection. Default, dry-run, CI, lookup and demo-start modes report incomplete output with zero operations. Offline fixture completion always reports `offline-fixture-not-source-qualified`. The version-2 extension permits only an explicitly injected transport and the qualified public-source plan/allocation below; `live` with an offline plan still rejects with `live-source-unallocated`.

`createFleetCollector` takes an explicit versioned plan, injected `source: {kind: 'offline', version, discover, solve}`, a canonical `PolicyService`, an absolute owned checkpoint path and `mode: 'offline'`. The plan contains schema/plan/version/seed, source ID/version, all F39 market/locale/catalogue/order/effect/production/tax dates, model codes, target, candidate count and finite limits. `policyRead: {asOf, policyVersion}` is required in the plan and independent of those catalogue dates. An optional injected read may add the run ID but must agree with that policy pin.

Limits explicitly declare each operation's lifetime request budget, maximum candidates, attempts per exact source request, timeout, absolute run duration, retry delay, cache entries/retention, checkpoint bytes, concurrency one and image requests zero. Discovery supplies the real VG/AG/range/trim mapping, typed selectable definitions and complete base elements. Candidates are reproducible seeded subsets or explicit discovered-code requests. Only the injected solver can establish constructibility.

Accepted records preserve the complete typed resolved factory and accessory selection, configurator model range, exact F39 catalogue request/lookup identity, decoded canonical identity and solver-added/removed/ignored requests. The semantic ID includes upper-case VG model and sorted unique complete factory codes, then padded standard Base64. Dates, source/version/request differences and accessory-only variants never increase the distinct configuration count. No VIN is assigned.

The CLI accepts only absolute explicit paths:

```sh
node scripts/gcsp/collect-fleet.mjs --plan /owned/plan.json --offline /owned/fixture.json --checkpoint /owned/checkpoint.json
```

The bounded JSON fixture has `discovery` and `responses`, with responses keyed by the deterministic `candidateId` returned by `buildCandidateQueue`. Missing responses reject rather than fabricate a result. The CLI prints counts, coverage and checkpoint location; complete records remain in the private checkpoint. Under-target output remains `incomplete`.

`collector.session.withCheckpoint(callback, {stage: {id, version, inputDigest}, initialState})` is the downstream seam. The callback receives `{state, stageState, execute, commit, stop, checkDeadline}`. F60 must predeclare its offline operations in the collector's `operations` and plan budgets before collection begins, then call `execute` on this same session. This retains the actual run's source identities, ledger, retry allowance, cache and deadline. Each stage owns its version/input digest/data. Changing the run plan, source, tool, policy or limits rejects checkpoint compatibility; changing an existing stage's version/input rejects stage compatibility.

Offline callbacks must respect their AbortSignal and supply offline data only. The session persists an attempt before calling the source, never retries projection/checkpoint failures as transport failures, and conservatively stops on 401/403/429. Writes use checksummed bounded envelopes, fsynced staging, atomic rename and directory sync. Unique writer markers prevent concurrent writers; recovery deletes only exact staging/marker paths recorded for a dead local participant. Unknown ownership is preserved for diagnosis. A run whose persisted absolute deadline has expired cannot gain another allowance by reopening the checkpoint.

This seam is tested with a synthetic facts operation; it does not claim F60 consumer integration, profile qualification, 200 accepted configurations, imagery or the deferred 10,000 run. F58 owns broader source qualification, F77 plan selection, F60 enrichment and F78 stock/sampling.

## Qualified public source, version 2

`source: {kind: 'public-bmw-uk', version: 'f58-20261105.v1'}` selects the known G61E/T5MJ observation plan, with only its five actually known market/locale/catalogue/order/effect fields and explicit known factory/accessory selection. It does not accept invented production/tax dates to satisfy F39. `mode: 'source-fixture'` requires `http: {kind: 'fixture', fetch}` and always labels observations `synthetic-http-fixture`. `mode: 'live'` requires `http: {kind: 'live', fetch, allocation: {id, sourceVersion, planDigest, attempts, bytes}}`; allocation and plan limits are bound into checkpoint identity. No CLI live default exists.

`public-bmw-source.mjs` supplies only four strict projection/prepare descriptors to the existing common session: page, settings, discover and solve. Their exact origins, paths and queries are independently checked by the session. Only GET, omitted credentials, no-store cache and manual redirects are permitted. Headers are empty on the configurator origin; only a bounded ephemeral `x-api-key` can be sent to the two pinned UCP capabilities. Qualified settings profiles are traversed within 30,000 nodes/depth 24. Header values remain closure-only; settings responses are never cached. The complete known solver selection and its factory/accessory classifications must agree exactly.

The model-tree projection has observation-only scope. It requires at least one full direct `group/modelRanges/G61E/models/T5MJ` record. Every full record found at that path must match six pinned literals: `modelCode=T5MJ`, `agModelCode=72HH`, `modelRange=G61`, `steering=RL`, `orderDate=2026-11-01` and `effectDate=2027-01-05`. Missing full records or a mismatch stops the observation; a compact `defaultModel` reference cannot qualify. The projection records the actual group keys in `sourceContext.fullRecordGroups`, without requiring exactly two groups or comparing additional projected facts. This differs from F58's qualified selector, which requires both groups `5` and `I`, their parent relations and equality of their complete projected fact sets. F59 does not claim equivalent two-group qualification. The actual 6 November pilot records both `5` and `I`, remains an unqualified source observation and supplies zero accepted corpus rows. F60 consumes validated accepted records and their exact F39 identities, not these group keys.

HTTP plans additionally declare total `sourceAttempts`, `sourceBytes` and per-response `responseBytes`; these limits cover every stage and resumed session. Counters include `httpAttempts`, `decodedBytes` and per-operation `operationBytes`. `sourceCalls` increments only for the explicit live transport. Consumed chunks are durably counted before retention, including a chunk consumed at the absolute deadline or over a byte limit. Complete-body timeout aborts/cancels and joins source work before another write/release. HTTP failures do not retry. Sticky status stops persist even when a downstream stage propagates the error without its own collector catch.

Only safe source projections enter the common cache/checkpoint. `sourceObservations` retains the canonical identity, actual complete source-typed selection, original four-code request, returned model context and observed timestamp. Catalogue key G61E and returned model range G61, request/returned effect dates and source observation date stay distinct. Model year is unknown, accessory quantity is null and paint/upholstery/trim, production/tax readiness remain unqualified. `accepted` stays empty; observations cannot silently become F39/F54 corpus rows. A completed observation resumes with zero requests. A partial resume cannot recover the memory-only header from disk or replenish the settings/request budget; it stops honestly if bootstrap is unavailable.

The sole 6 November pilot consumed exactly four GET/200 and 782,059 decoded bytes through this collector/session, retaining one known source observation, zero additional configurations and zero accepted corpus rows. The allocation is consumed and cannot be rerun. See `source-executor-2026-11-06/` for executable/source pins, safe observation and resource/validation receipt. Tool/session versions are both 2; version-1 checkpoints reject compatibility rather than mixing counters.
