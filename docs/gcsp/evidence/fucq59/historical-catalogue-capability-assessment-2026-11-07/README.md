# Historical catalogue capability: read-only assessment

A bounded historical G26E probe is technically possible through the existing public BMW tree route, but successful historical data support is unverified. No new source request was made during this assessment. The accompanying finite proposal is not executable and grants no source traffic.

The retained eligibility matrix explicitly says orders from 1 October 2024 and lists i4 M50 at lines 70 and 146. The actual G26E diagnostic from 7 November 2026 instead returns I4PC as `I4 M60`, with order date 1 November 2026 and model effect date 5 January 2027. It supplies no M50 observation and cannot close the historical M50 join. The current public page has no evidenced historical date parameter; a current model seed is only a transport/bootstrap lead.

The tree route has separate request effect and order date segments. Existing historical F44 evidence already executed 1 October 2024 for both dates with `future-models=false` and `closest-fallback=false`. On 5 November 2026 that exact three-GET run stopped at HTTP 400 from the tree and returned no model context. Its cause is unknown: it neither proves nor disproves historical support for G26E or other ranges. F44's spent request is not proposed for replay.

The concrete next candidate is one G26E query at 1 October 2024 for both request dates, with both flags false, bootstrapped from the retained literal G26E/I4PC page. It is at most three serial GETs, 45 seconds, 4 MiB decoded bodies, 256 KiB retained projection, 32 MiB scratch and 256 MiB RAM. It includes no options, solver, image, browser, retry, date sweep, flag fallback or source write. Selected dates remain request probes; the response must independently supply its model/AG/range/steering/order/effect/derivative facts.

The current generic inventory registration hardcodes both flags true, so it must not be described as a no-fallback historical query. The smallest preparation is a finite specialization of the existing historical evidence-only client, retaining direct derivative facts through the existing safe inventory rules. It requires scoped offline checks and an exact parent source release before execution; no new human source-permission hold is introduced. No production adapter or optional framework expansion is proposed.

Any successful response is still catalogue evidence only. M50 absence, empty output, refusal, changed dates or a returned M60 stays explicit evidence of that selected response. Current badges are never substituted. Constructibility, scheme eligibility, production era/model year/plant, profile/WMI coverage, 10,000 actual admissions and downstream acceptance remain separate open gates.

All read inputs are hashed in `finite-probe-proposal.json`. This document/proposal change needed no code test or scratch allocation; the prior historical and actual G26E proofs are reused at their recorded identities without source/test replay.
