No source request, clock, marker or durable output root is created by preparation. The original 1,133 admitted source configurations remain the baseline. A candidate is not a configuration credit: actual strict source binding and cumulative canonical admission determine the result.

Implementation and validation scope: new evidence-package files only. Existing registration, public source, collection session, binder, canonical-key and resource helpers are reused without modification. The regression to check is exact finite pool enumeration, all spent-request exclusions, actual model/line/type provenance, the unchanged model route, correct per-session/cohort/phase accounting, pinned executable identity, and pre-release absence of markers/output. The affected-test selector's generic npm-test fallback is reviewed rather than executed; the selected check directly validates every frozen template and input. For source execution, each session uses one worker, 64 MiB owned default scratch, 512 MiB host RAM and a 448 MiB child limit, with 120 seconds for source and 30 seconds for retained verification. Each phase's clock starts only when its separately authorised one-shot marker is created, and is never reset. Expected retained output is 320 MiB; the hard total is 1 GiB, with at most 16 MiB per session and 64 MiB transient scratch. Every durable byte goes directly to the declared OneDrive root; ownership is recorded outside that root before allocation. Each session must prove source/export/cumulative-index semantics and scratch/process/reservation cleanup before the next is prepared. The outer finalizer joins owned children and audits actual helper manifests, preserving primary evidence on failure.
