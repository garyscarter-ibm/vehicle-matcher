## Planned port and states

`createOfferFollowupService({ repository, policy, clock, identity, brief, offers, evaluations })` requires the actual injected authorities. `read(context, { decisionId })` verifies the employee's persisted decline and its matching completed106 receipt; `confirm(context, { commandId, decisionId, expectedBriefVersion, questionVersion, value })` additionally derives the sole allowed path from canonical policy and calls BriefService. No browser-selected path, identity or reason code is authoritative. `questionVersion` binds policy, decline and current brief. Source failures remain typed unavailable; missing/malformed canonical keys have no local defaults. Read/mount/selection alone never writes.

The proposed `offer.followupQuestions.v1` key selects exactly one question for each106 typed reason. Body/fuel options use registered enum values; size uses canonical slider bounds; equipment changes one existing complete equipment essential. Missing target fields or unsupported choices remain unavailable/invalid instead of inventing input. Employee confirmation supplies provenance/time through BriefService. Its canonical FUCQ-30 action remains the sole change reducer.

Reload derives `question`, `change-saved`, `waiting`, `ready`, `no-match` or `unavailable` from persisted brief/history, decline/event and actual subsequent service results. Save exposes the real new brief version and event. Waiting requires a successful source read; an absent allocator/evaluation source is unavailable. No-match requires a completed actual evaluation tied to the changed brief/release with no suitable allocation, never an empty fixture or missing capability. Ready requires an actual later stored offer/hold/quote for this employee/renewal and changed brief. The declined exact order remains excluded unless the canonical relevant-change rule permits re-evaluation; no follow-up allocator or exclusion map is added.

Comparison uses two stored quotes and the current approved brief. It reuses105's safe public projections, retains unknown facts/units/provenance, distinguishes historical score from current measured facts, and names only explicit confirmed requirements/preferences. It never invents a better fit, hidden preference or second winner. Two same-car quotes do not establish an unchanged-car exclusion proof.
