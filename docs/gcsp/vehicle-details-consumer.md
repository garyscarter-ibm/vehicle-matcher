# Application vehicle-details port

FUCQ-56 follows the leading 4 November Q7/Q13 Jira rescope. The application calls FUCQ-55's public lookup port **in process**. The historical HTTP-adapter criteria are superseded; the real HTTP route remains an external boundary proved by ephemeral contract tests. No new route, screen, service, database or runtime dependency is added.

```js
import { createConfiguredVehicleDetails } from '../../server/gcsp/vehicle-evidence/application-vehicle-details.js';

const vehicles = createConfiguredVehicleDetails({ lookup }); // server-owned composition
const result = await vehicles.resolve({ kind: 'stock', id: orderUuid,
  expected: { configurationId, datasetId, corpusVersion } }, { context });
```

`lookup` is FUCQ-55's read-only `resolve` and `classifyRequest` port. It continues to verify current-run stock via TransactionRepository and immutable configuration/VIN associations via the registry. The consumer accepts canonical padded Base64 configuration IDs, lower-case UUID-v4 stock orders and trimmed/ASCII-uppercased delivered/current VINs using that port's existing identifier function. Stock requires server-owned current-run context. No stock VIN is manufactured; the seven-digit order number remains a display field.

`createVehicleDetailsConsumer({ adapter })` is the application-service interface. It returns `{ contractVersion, status, vehicle, failure, transport }`. Success has a provider-independent `vehicle` projection with requested/resolved identity, synthetic/configuration/vehicle/dataset/origin identity, versions, description, technical values, equipment, images, source evidence, completeness and presentation labels. Failure has `vehicle: null` and a safe typed code/message/action/retryability. Provider storage names and exceptions are not application facts. A malformed/unknown-version payload cannot become a successful empty object.

Trusted `expected` pins support configuration/vehicle/dataset/origin, corpus/snapshot versions and profile ID, model, market, body, fuel, AG/VG codes and physical/catalogue dates. Wrong or missing pinned evidence is `identity-mismatch`. The consumer also checks requested/resolved lookup identities, canonical configuration codes and source requested/resolved model/market/date/options agreement before accepting facts. It never looks at retail defaults, eligibility, points, terms or usage data.

Provider selection belongs to server construction. `provider: 'alternate-offline'` with `alternateRead` exercises a deliberately fictional card/document shape: composition/order/delivered keys, renamed identities, measurement rows and image cards. The retained test fixture transcribes the two existing tiny FUCQ-55 records and their current-car/stock associations. This demonstrates replaceability and preserves the retained source facts; it supplies no guessed BMW/Outvin schema or production-access claim. Each adapter has a configured timeout of 1–5000 ms and one or two attempts; defaults are 1000 ms and one attempt. Abort signals reach every provider attempt. Transport protocol/status/attempts/outcome remain separate from complete/partial/capability outcomes. There is no HTTP transport in the application adapter or live fallback.

FUCQ-57 makes identity classification mandatory for configured providers. The default `lookup` also supplies `identityLookup`; an alternate provider must receive the same trusted `identityLookup` explicitly. A missing classifier fails unavailable before reading the provider. VIN/configuration classification reads the independent durable publication inventory, including inactive/history-only identities. Stock classification validates the whole FUCQ-53 snapshot and its revision/digest in the actual current run, then checks the exact UUID, stock usage and retained configuration. A valid-looking VIN or browser flag never supplies authority. An empty/unselected corpus is unavailable; a genuine unknown in an available closed corpus returns an offline miss without consulting the alternate provider.

Each bounded attempt classifies before its offline read and checks cancellation before provider entry. Successful reads are reclassified and compared with the retained configuration/vehicle association, including after a concurrent reset. Redirect/error transport statuses cannot select another URL or a live fallback. Server construction supports only `lookup` and `alternate-offline`. The separately merged FUCQ-43 guide guard remains the common boundary for any future externally authorised real lookup; this port supplies no real authorisation or credentials.

Source citations retain their public language parameter when it is the sole `language=xx` or `language=xx-XX` parameter, preserving the existing WBS Munich citation exactly. Other query parameters, credentials and private hosts remain rejected. Image/asset references retain the stricter query-free rule. These are metadata validation rules; no source or image URL is fetched by this consumer.

Source catalogue facts retain their own field provenance separately from the fictional identity association. Selected catalogue equipment stays distinct from verified physical fitting, which remains unknown. Missing appearance/technical facts, source dates, measurement meaning/units and physical versus catalogue production dates survive both adapters. Images remain absent or explicitly representative by role/fidelity. The representative-image test uses a labelled fictional contract reference with no asset, rather than introducing unapproved runtime imagery.

This backend capability changes no rendered surface.
