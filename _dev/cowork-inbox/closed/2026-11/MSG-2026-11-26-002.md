The `--except _tools/test_stack.py` instruction is lifted. `_tools/test_stack.py` in vehicle-matcher is now the agent-scaffolding kit's (1.2.1, kit 0.17.1): the GCSP fork is retired (SCAF-71, SCAF-77 to 81), in gcsp-poc-dev commit 8329d6099. A plain `inbox_setup.py update` is safe again.

What changed for you:
- `_tools/test_stack_build.py` is gone. Use `python3 -B _tools/test_stack.py node link --app ...` and `test_stack.py build api|web --worktree ...` instead (same flags, same `PROOF_API_JAR=` / `PROOF_WEB_BROWSER=` output).
- A heavy child now sees `AGENT_HEAVY_SLOT`, not `GCSP_HEAVY_SLOT`. The state root is `$AGENT_TEST_STACK_DIR`, or `~/Library/Caches/agent-scaffolding/test-stack`. e2e/run.py and browser-ci-batch.py are switched already.
- There is no `heavy --slots`. Slots are the machine's, set as `test_stack.heavy_slots` in `~/.config/agent-scaffolding/machine.json`.
- Daytime RAM cap: outside the machine's night window, a heavy request above `daytime_max_gib` (3) exits 75, "run overnight or in CI". The web e2e runner asks for 3.5 GiB, so it runs at night or in CI. CI (`CI=true`) is exempt. Exit 75 means "not now", never a test result. Don't pass `--allow-daytime`.
- Config is the `test_stack` block of `.claude/scaffolding.json`. `postgres.bin` is `${GCSP_PG_BIN:-Homebrew}` and `maven.java_home` is `${JAVA_HOME:-Homebrew openjdk@21}`. For the kit on your Mac, install the kit's 0.17.1 (`tools/update`).
- The old `~/Library/Caches/gcsp-test-stack` cluster is no longer used. `test_stack.py gcsp-legacy status` shows it. Once it lists no databases, `gcsp-legacy down` stops it (it deletes nothing).
