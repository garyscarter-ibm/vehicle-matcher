acceptance:
- [x] **Seed file:** a reviewed, machine-readable seed at a single repo location (for example `server/gcsp/policy/seed-v1.json`), shaped like the target model:
  dated scheme-rule links;
  include/exclude eligibility rules matching on a keyed field;
  a per-scheme dated price plan (the monthly points cost per car);
  a company/grade allowance;
  keyed assumptions.
  The October 2024 Choices matrices (`docs/gcsp/sources/choices-eligibility-matrices-2024-10.md`) supply the BMW rules.
- [x] **Keyed assumptions:** every assumption has a stable key, value, unit, `assumed` or `verified` status, a short basis and its source and date. The seed includes at least:
  the cart hold of about 2 minutes;
  the order-review phase;
  the buddy offer hold of about 2 hours;
  the allocation tie-break rule;
  the declined-car exclusion;
  the unused £1 per point top-up;
  the home-charging rule, labelled a demo assumption, not a BMW rule;
  synthetic release sizes and lead times.
- [x] **One read interface:** a `PolicyService` with the interface recorded in `docs/gcsp/shared-contracts.md` (FUCQ-80). It returns the active policy version and typed reads: eligibility for a context and car, allowance, points cost, and named assumption values. Every result carries the policy version it came from. An unknown key, scheme or grade fails explicitly, with no fallback default.
- [x] **Read-only first:** this story serves the seed through a file-backed provider. FUCQ-83 adds the dated PostgreSQL tables behind the same interface, and consumers do not change when it does.
- [x] **Tests read the source:** tests read their defaults through `PolicyService` and may pass explicit alternatives. A test proves that changing one seed entry changes the value every consumer receives.
- [x] **build-rules.md updated:** `docs/gcsp/build-rules.md`, "Plausible assumptions in one shared source", rule 2, records the source's repository location and the access interface, as that file requires of the first such story.
