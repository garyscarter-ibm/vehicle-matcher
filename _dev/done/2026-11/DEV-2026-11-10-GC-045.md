goal:
  GCSP pages load in about one round trip of static files instead of five or six, and a page the browser has seen since the last deploy loads its JS and CSS with no network requests at all.

  Measured 10 Nov on gcsp-poc 8ec4b25b (local memory host, desktop Chrome, 100 ms added round trip, about what the hosted demo costs from the UK): presenter 3.6 s cold and 3.6 s warm (133 static requests, 88 JS and 43 CSS, import depth 5 to 6, no modulepreload); offer 2.7 s; outbox 1.7 s. With no added latency the same pages take 1.0 s, 0.7 s and 0.6 s, so about 2.6 s of the presenter load is round trips. FUCQ-302 made the API about 5 ms per call; FUCQ-303 made static files revalidate with 304, but every file is still asked about on every load, so a warm reload is no faster than a cold one.
acceptance:
- [ ] Every GCSP page served by `createGcspFront` references its static JS, CSS and images under a versioned prefix `/_v/<version>/...` (the HTML on disk is unchanged; the server rewrites `./blocks/`, `/blocks/`, `./assets/`, `/assets/` and root `gcsp-*.css` references when it serves a page).
- [ ] A static file requested under the current version is served with `Cache-Control: private, max-age=31536000, immutable` and its ETag. Under any other version it is served as today (`private, no-cache`, ETag, 304). Unprefixed static URLs behave exactly as FUCQ-303 left them.
- [ ] The version changes whenever any file under `blocks/` or `assets/`, or a root `gcsp-*.css`, changes (size or modification time), including while the server is running, so a redeploy or a local edit is never served stale.
- [ ] An HTML page requested under the prefix (for example a module's `new URL('../../../gcsp-presenter.html', import.meta.url)`) redirects to the unprefixed page with its query kept, so session, presenter and Greg gates still apply.
- [ ] Each served page's head carries `<link rel="modulepreload">` for every module reachable by static import from its module scripts, and `<link rel="preload" as="style">` for every stylesheet reachable by `@import` from its linked stylesheets, all under the versioned prefix.
- [ ] Path safety is unchanged: anything under `/_v/` that resolves outside the public static paths is a 404, and the access gate behaves as before.
- [ ] Measured with the same method as above (median of 3): the presenter page at 100 ms round trip loads in under 1.5 s cold and under 1.2 s warm; offer and outbox improve too; warm reloads make no static requests. Every page still renders and works (no console errors, presenter strip opens).
files_or_areas: `server/gcsp/host.js` (`createGcspFront` static and HTML branches), a new helper module beside it, `server/test/gcsp-host-cache.test.js` and a new test file. No block or page HTML changes.

result: built
- change: `server/gcsp/static-version.js` (new) and `server/gcsp/host.js`. Served GCSP pages rewrite `./blocks/`, `/blocks/`, `./assets/`, `/assets/` and root `gcsp-*.css` refs to `/_v/<version>/...` and gain `modulepreload` for every statically imported module and `preload as=style` for every `@import`ed sheet. Current-version static files are `private, max-age=31536000, immutable`; other versions and plain paths keep FUCQ-303's `private, no-cache` + ETag. The version is a hash of path, size and mtime over blocks/, assets/ and root gcsp-*.css, rechecked at most once a second. A page under `/_v/` redirects 303 to the plain page (query kept) so its gate runs. Page HTML on disk unchanged.
- measured (docs/gcsp/evidence/fucq-374/summary.md, median of 3, 100 ms RTT, desktop): warm presenter 968 to 232 ms, warm offer 2223 to 562, warm outbox 1189 to 454, warm login 976 to 129; cold offer 2264 to 1771, cold outbox 1193 to 666, cold presenter 924 to 806. No page errors. AC 7's 3.6 s presenter baseline no longer applies: today's presenter revamp cut that page to 32 static files before this change.
- tests: new `server/test/gcsp-static-version.test.js` (4) and gcsp-host-cache (2): 6/6. Host-front suites (hosted-entry, login, live-image-route, brief-runtime, cases-local-demo, offer-access, shell, hosted-comparison-result, activity-live): 108 run, 107 pass, 1 fail. The fail, gcsp-activity-live "actual live entry bootstraps...", expects 200 from an unauthenticated live page and gets 303 to sign-in; it fails the same on the base host.js, so it predates this change (today's login work). No full suite.
- not measured: account and Greg pages (need a signed-in user in the probe); hosted Render timing after deploy.
