goal: The hosted dev demo can be signed into without an external identity provider. A labelled demo sign-in issuer, built into the Java API and switched off by default, signs in the demo scenario's fictional people through the same OIDC code + PKCE flow the Angular app already uses, so hosted Render needs no outside account and a real provider later is a configuration change only.
acceptance:
- [ ] With the demo issuer switched on, the Java API serves an OIDC issuer under its own origin: discovery, JWKS, an authorization page, a token endpoint (authorization code with PKCE S256, and refresh) and end-session. The authorization page is labelled "Demo sign-in. Fictional people only." and lists the demo scenario's people (employees, Greg and the presenter) with no passwords. Choosing one returns to the Angular callback signed in as that person, with that person's roles and employee mapping.
- [ ] The API checks these tokens through its existing OIDC validation (signature against the issuer's JWKS, issuer, audience, lifetime, authorised party, scope, roles and subject mapping), with no bypass. Sign-out ends the demo session, so a different person can then sign in. Renewal works through the refresh grant.
- [ ] It is off by default and cannot be switched on by accident: it starts only with the explicit switch, only with the OIDC identity provider selected, and only with the demo scenario provider (fictional data). Any other composition refuses to start with a clear message. Its signing key survives an ordinary restart, so a restart does not sign everyone out.
- [ ] `render.gcsp.yaml` switches it on for the isolated dev services and fills every identity setting it determines (issuer, JWKS address, audience, authorised party, scope, role claim, subject mapping, and the Angular `GCSP_PUBLIC_OIDC_*` values), leaving only values Render cannot know in advance, if any, as `sync: false`. The cutover and release hand-over docs say hosted sign-in uses the demo issuer.
- [ ] One connected proof that today starts the script's local mock issuer (for example `scripts/gcsp/fucq439-connected-shell-proof.mjs`) passes against the demo issuer served by the started Java API instead: sign-in, renewal, expiry, sign-out and a second person signing in. Desktop 1280, keyboard with visible focus on the sign-in page.
