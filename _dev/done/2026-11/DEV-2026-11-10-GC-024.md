- diagnosis: confirmed in headless Chrome 157 over CDP. As served, `/gcsp/offer` is `Cache-Control: no-store`, so Chrome never
  keeps it in BFCache (`MainResourceHasCacheControlNoStore`) and Back does a fresh, correct load. With no-store stripped (the case
  for Safari/Firefox or a future header change), Back restored a persisted page with an empty `<gcsp-offer>`: entry-harness
  disposed the entry on every pagehide, which emptied the root and removed the only pageshow listener. Fix: dispose only on a
  non-persisted pagehide. The installed session lifecycle (shell) then clears the person on persisted pagehide (no cached
  former-user data) and reloads on persisted pageshow, so the server re-decides who is signed in. The shell's reload now routes
  through the entry's `location.reload`.
