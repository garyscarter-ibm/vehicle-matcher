goal: As Paula opening her offer email in any browser, I want the link to show me exactly where my offer stands now, so that an old or forwarded link can never mislead me or revive a hold.
acceptance:
- [x] **Exchange route:** a `/api/gcsp/offers/access` route exchanges the opaque token from the offer link (minted by FUCQ-100) for an offer access context scoped to that one offer. The token is looked up by hash. Its environment, run and offer binding are checked, and it is never logged. Evidence: `server/gcsp/offers/access-http.js:50` (POST route), hash verify `access.js:171`; tests `gcsp-offer-access.test.js:87`, `:186`, `:326`.
- [x] **Offer read:** the offer read returns server-derived current state: pending (with the expiry time from the persisted hold), accepted, declined, expired, superseded or stale run. It includes the pinned quote, the vehicle facts and the comparison inputs, and nothing about the employee's other offers, fleet or usage history. Evidence: `gcsp-offer-access.test.js:101` (stored states), `:114` (persisted deadline), `:164` (stale run), `:196` (one-offer projection); safe DTO in `docs/gcsp/offer-access-contract.md`.
- [x] **Old links:** repeated, old or stale links read the current state and never extend or revive a hold. A link from an earlier run returns "this offer belongs to an earlier demo run". An unknown or tampered token returns a generic not-found response. Evidence: `gcsp-offer-access.test.js:114` (no revival), `:153` (generic not-found), `access.js:9` earlier-run copy; `gcsp-offer-access-producer.test.js:168` (actual expiry/reset).
- [x] **Account route:** a signed-in employee (FUCQ-84 context) reaches the same offer from their account without a token. Both routes produce one offer access context, and decisions (FUCQ-89, decision story) accept either. Evidence: `gcsp-offer-access.test.js:251`, `:265`; `gcsp-offer-runtime-composition.test.js:178` (FUCQ-105: a leftover invalid offer cookie falls back to account access; a cookie alone still 404s, consistent with this AC).
- [x] **Landing URL:** the landing URL comes from deployment configuration for the GCSP static site (Q1), never hard-coded. Evidence: `server/gcsp/runtime.js:39` reads `GCSP_OFFER_LANDING_URL`, declared `sync: false` in `render.yaml`; `gcsp-offer-access-producer.test.js:133`, `gcsp-offer-token-coordinate.test.js:21`. Hosted value not yet set (no GCSP static site deployed).
