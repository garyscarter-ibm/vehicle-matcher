goal: As Greg, I want a clean record of what employees wanted, what they could get and what they chose, so that a demand model can learn from it without mixing synthetic history with what really happened.
acceptance:
- [x] **Record shape:** a `LearningRecord` shape is added to `docs/gcsp/shared-contracts.md`. Each record carries:
  the renewal cohort and period, and the entitlement context (scheme, grade, allowance band);
  the confirmed brief version, with preferences, importance weights and essentials;
  the choice set: the eligible and available alternatives at the time, and how long each was exposed;
  the dated points terms that applied;
  the outcome: offered, selected, declined (with its typed reason), expired, or waited with no acceptable choice;
  timestamps from the demo clock;
  provenance: `observed` or `synthetic`, with the generator version and seed for synthetic records.
- [x] **Distinct outcomes:** acceptance, decline, expiry and later satisfaction are separate fields. A fit score is never written as an outcome or as satisfaction.
- [x] **Observed records:** a projection over FUCQ-81's repository builds observed records for the current run from the same saved briefs and offer outcomes that FUCQ-99 aggregates. It holds no employee names, trip or usage history.
- [x] **Synthetic generator:** a seeded generator produces plausible multi-cycle records. It includes noisy responses, no-choice outcomes, competition and supply limits.
  Synthetic employees are generated from PolicyService keys (cohort size, preference and importance distributions, noise, no-choice rate). None is hard-coded.
  Vehicle alternatives come from FUCQ-77's real configurations.
  The same seed and policy version give identical output.
- [x] **Manifest:** each generated dataset writes a manifest with record counts, cycles, seed, generator version, policy version and the configuration set it used. Training (the next Story in FUCQ-74) reads only datasets with a manifest.
- [x] **Kept apart:** observed and synthetic records are never mixed in one dataset without their provenance, and a test proves it.
- [x] **One central change:** changing one generator key in the policy source (for example the no-choice rate) changes the generated records, with no code edit.
