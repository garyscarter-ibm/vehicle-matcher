goal:
  Found by FUCQ-226 (DEV-2026-11-08-GC-043), 9 Nov 2026. FUCQ-226 fixed memory mode: `MemoryPolicyProvider.loadVersions` returned a fresh clone of the 562 KB seed on every read, which defeated PolicyService's identity-keyed cache. In PostgreSQL mode the same reads go to the database, about 5 million policy queries for the default 1,000 x 3 run. So `scripts/gcsp-comparison.mjs` can't usefully replay in PostgreSQL mode. FUCQ-137 stores the demo's result through the configured repository, which is PostgreSQL on the hosted demo.

  **Workaround until fixed:** replay in memory mode with `--out`, then store the file with `--import` into PostgreSQL.
acceptance:
- [ ] A replay never reads policy from PostgreSQL per call. Policy versions are loaded once per run (or cached by version) and reused. The replay itself always runs in memory, and only the stored result goes to the configured repository.
- [ ] The default 1,000 x 3 run in the hosted configuration takes no longer than memory mode (about 20 min, under 3 GB), and makes at most a small, fixed number of PostgreSQL queries for policy.
- [ ] Measures and digests are identical to a memory-mode run.
- [ ] The command's help text and docs state where the replay runs and where the result is stored.
