goal: As the presenter, I want every GCSP request to act as a known fictional person within the current demo run, so that nobody can act for another employee or gain Greg's powers by changing an ID.
acceptance:
- [x] **The adapter:** a `DemoIdentityAdapter` (interface in `docs/gcsp/shared-contracts.md`) resolves only configured fictional principals:
  employees, for example Paula, plus competing employees, each with a scheme, company, grade and entitlement slot;
  Greg, the scheme and ordering lead;
  the presenter.
  Principals are seeded into FUCQ-81's employee tables per run, with no real names, contact details or licence data.
- [x] **The gate:** the adapter sits behind the existing demo access gate (`DEMO_ACCESS_KEY`, `isAuthorized` in `server/index.js`). The shared password alone is not a principal. The presenter picks or switches the acting principal through a server-issued session the backend owns. Use an HttpOnly cookie or an equivalent, with no token in URLs or logs.
- [x] **Server-owned context:** each `/api/gcsp` route receives one context object (principal, roles, scheme context, `runId`) through shared middleware. A route without it rejects the request. Employee ID, grade, scheme, role or run supplied by the browser is ignored or rejected, never trusted.
- [x] **Role checks:** policy publish, order requests and other Greg operations require the Greg role, and reset and ticks require the presenter role. An employee cannot read another employee's brief, holds or offers. Tests cover each refusal.
- [x] **Run isolation:** each run has a `runId`. Every repository read and write is scoped to the context's run, and a command whose objects belong to another run is rejected as stale.
- [x] **Replaceable:** the adapter can be swapped for sanctioned BMW identity and roles later, with no route changes. This is recorded in the contracts file.
- [x] **Outcomes:** unknown, missing and expired sessions return distinct outcomes, and the retail routes are unaffected.
