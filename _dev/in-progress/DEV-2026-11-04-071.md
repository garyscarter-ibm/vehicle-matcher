- [ ] Submit checks principal/entitlement, exact live claim and expiry, draft/stock/policy versions, pinned terms/quote validity, required contact/return data, driver/licence and all applicable declarations again. Reject stale/expired/invalid submissions with reviewable reasons, without releasing confirmed ownership to another chooser mid-operation.
- [ ] Persist selection-received and pending handoff before an external-shaped write; an acknowledged synthetic adapter returns one generated order reference plus the actual approval-pending state. Repeated/double-click/retried requests return the same operation/order, never duplicate orders.
- [ ] Persist unknown/time-out outcomes using the same operation/idempotency key, and reconcile them before retry or reallocation. Reconciliation registers as a tick handler on FUCQ-85's clock, not a private timer. A failed or unsupported provider never produces an approval, order number or confirmation invented by the UI.
- [ ] Model the configured approval stages as returned order status, in the target platform's names (Q19): HR approval (only where the policy key includes it), sales-manager approval, then sent to ordering. Build no approval workflow. Preserve snapshot terms/quote/employee/driver/old-contract/vehicle-slot facts for readback and print; new quotes do not silently change the recorded selection.
- [ ] Read/reopen/restart returns current pending/acknowledged/failure state and updates account history from the same store. A selection or awaiting-approval order does not confirm collection, end/return the old contract or replace the employee's current-car relationship.
- [ ] Prevent a second active selection for the same renewal/entitlement and stop competing manual claims for that slot after acknowledgement. This adapter is the common authority: FUCQ-108 calls it to hand off a selected buddy offer, so it takes the claim or hold being converted as an input and does not assume a manual claim. It adds no buddy offers, events or mail itself.
