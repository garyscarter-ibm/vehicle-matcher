- diagnosis: unchanged response with no feedback. `refreshCurrent` (`blocks/gcsp/offer/offer-view.js`) ran `clearFollowup(); refresh?.()` and dropped the promise. The read itself works (the HTTP adapter fetches with `cache: 'no-store'`) and a changed state does redraw. But when the read came back the same, `update()` skipped `draw()` because the structure key matched, and the view announced nothing because the state and identity were unchanged. So an unchanged check left nothing on screen and nothing for a screen reader. It is not stale rendering, and no request fails. A failed readback already drew the error screen, but nothing said the check had happened.
- component plan: reuse `button` (the existing ghost refresh control, label unchanged); reuse `viewStatus` (the view's one live region, cleared at the start of a check so the same result is announced again); a plain `gcsp-note` paragraph under the button for the visible line (the shell's existing note style, no new class or CSS); reuse `statusScreen` and `factList` unchanged through the existing error and accepted paths. No new or extended component. ui-ratchet passes with its baseline unchanged.
- change: the check now shows "Checking the current offer state." while the read runs. When the read settles it shows one of: "Check complete. Nothing has changed.", "Check complete.
