goal:
  As Gary presenting on 12 November, I want the hosted GCSP site and backend on Render to run the whole demo (Paula, Greg, presenter controls, outbox and real email), so that nothing depends on a laptop running a local launcher.

  Why:

  The HLD says GCSP runs in its own Render environment, built from `gcsp-poc`. Today, though, the Render backend starts with `node index.js`, which calls `buildServer()` with no GCSP dependencies. Every `/api/gcsp/*` call answers "GCSP identity has not been configured". Only `scripts/gcsp-demo.mjs` composes the GCSP runtime (identity, repository, policy, stock, clock, mail and presenter controls). Gary decided on 7 Nov that everything should be hosted. This is a Must for the demo.
acceptance:
- [ ] **One composition:** the hosted entry point builds the same GCSP runtime and dependencies as `scripts/gcsp-demo.mjs`, through one shared module that both use. There is no second, drifting copy. Without the GCSP settings, `node index.js` behaves as it does today: the retail API only, and GCSP returns its existing 503.
- [ ] **Configuration by environment:** the backend reads its repository mode (memory by default for the demo, postgres optional), allowed origins (the `gcsp-site` origin), offline evidence, mail and the scenario from backend environment variables. The required variables are declared `sync: false` in the Render blueprint and listed in `docs/gcsp/render-postgres-setup.md`. No secret goes in git.
- [ ] **Hosted pages connect:** the `gcsp-site` static build points at `gcsp-api`. The launcher's employee and presenter entry, Paula's pages, Greg's pages and the outbox work against the hosted backend without `?fixture=`.
- [ ] **Proof the way Render runs it:** a test starts the server the way Render does (`node index.js` with the GCSP settings) and drives a reset, a tick and an offer through HTTP. A local browser check at 1280 and 375 runs against that process.
- [ ] **Deployed smoke:** after the merge to `gcsp-poc` and Render's redeploy, a smoke check of the hosted site covers the presenter reset, a tick, Paula's offer and the outbox. Evidence is retained.
out_of_scope: Speeding up postgres mode further (FUCQ-177 is done, and the demo uses memory mode). Real-email evidence is FUCQ-98, once this is deployed.
