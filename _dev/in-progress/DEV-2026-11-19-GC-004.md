story_link_basis: FUCQ-439 built the Angular sign-in and session handling in `oidc-auth.service.ts`, including the catch that reports sign-in as unavailable.
reproduction_steps:
  1. Start the Java API with the demo issuer on (FUCQ-532), a short access-token lifetime and refresh tokens on, and the Angular app pointed at it.
  2. Sign in as Paula, then let the refresh token lapse or end the session at the issuer.
  3. Let the access token expire and return to the app.
expected_behaviour: The app shows "Your session expired. Sign in to continue with your saved progress." and the sign-in action leads to the demo sign-in page.
actual_behaviour: The renewal is refused with `invalid_grant`. The catch in `initializeSession` (`oidc-auth.service.ts:114`) then shows "Sign-in is not available. Check that browser session storage is allowed, then try again.", so the person cannot continue (run fucq532-1148, scenario ac2b, page text). Hosted, this will happen to anyone whose 12-hour refresh token lapses.
