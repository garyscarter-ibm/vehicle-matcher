goal:
  As the demo owner, I want to reuse FUCQ-61's collected BMW configuration corpus, prove which scheme model lines it covers and verify configurator round trips, so every car selected for the demo has traceable constructibility evidence and only genuine coverage or evidence gaps require further collection.

  Context:

  Gary's 4 November decision uses real BMW configurations with synthetic stock on top. FUCQ-61 has since delivered a retained, verified cohort of exactly 10,000 distinct configurations; it is In Review, not accepted as Done. This story now starts with that corpus and its original source, solver and FUCQ-60 enrichment evidence rather than collecting a separate demo set from scratch. Map existing records to every line in the October 2024 scheme matrices, select a qualifying demo subset, verify the configurator links and collect or enrich only evidenced gaps. FUCQ-78 can use the existing corpus for its synthetic-stock work without waiting for this story's final coverage report. Corpus size alone does not prove scheme eligibility, current model mapping, facts, images, prices or stock availability. The retained basis is `docs/gcsp/evidence/fucq61/exact10000-closeout-2026-11-07/README.md`.
acceptance:
- [ ] **Plan.** A committed demo plan (`server/data/gcsp/vehicle-evidence/demo-plan.json`) lists every model line in the October 2024 eligibility matrices (`docs/gcsp/sources/choices-eligibility-matrices-2024-10.md`).
  Each line is mapped to a current UK configurator model range and model code, and carries its grades and towbar flag.
  A line with no current model is listed as an exclusion, with the reason. It is never mapped to a similar-sounding model; see the 330e-to-320i substitution in the research doc.
- [ ] **Corpus coverage and gap collection.** At least 8 distinct configurations per mapped model line, and at least 200 in total.
  Each is varied across paint, upholstery, wheels and at least one pack.
  Each is resolved by the rule solver (`constructible: true`) and stored with its full resolved option list.
  Requested-versus-resolved changes are recorded. A configuration whose model code changed during solving is rejected.
  Select qualifying FUCQ-61 records first, retaining the dataset/version, canonical IDs and original source/solver/enrichment evidence. Existing and newly collected records must meet the same criteria below. Collect or enrich only missing coverage or evidence; no blanket recollection is required.
- [ ] **Identity.** Each record stores:
  `vgModelCode`, `agModelCode`, the configurator `modelRange` and `modelYear`;
  the sorted factory option codes, with paint and upholstery included and dealer accessories excluded;
  the catalogue effect and order dates;
  `configurationId`, computed exactly as in the HLD section "Synthetic identifier formats".
  The verifier recomputes every ID and rejects any duplicate.
- [ ] **Facts and images.** Through FUCQ-60's enrichment, each record carries OTD technical values (0-62, seats, boot, range or economy, CO2) and at least one COSY exterior render reference, each with its source and observation date. A missing value stays explicitly unknown; it is never invented.
- [ ] **Configurator link.** Each record yields the deep link `https://configure.bmw.co.uk/en_GB/configure/{modelRange}/{modelCode}/{sorted options}`.
  A sample of at least 20 links is opened in a headless browser. Each check passes only when the page's resolved option list equals the record's.
  The pass and fail counts go in the collection report.
- [ ] **Budget and safety.**
  Any new gap collection stays within the original 3,000-source-request limit at concurrency 2 or lower, and stops or backs off on 401, 403 or 429.
  It resumes from checkpoints after interruption, and never runs in CI or at demo start-up.
  The report states the request count, rejections, duplicates and elapsed time.
  Nothing in artifacts or logs contains the key, a real VIN, a real order number or an opaque image URL.
  The report distinguishes reused FUCQ-61 records and their historical source receipts from new requests made for this story; report zero new source requests when reuse closes all collection gaps. Historical FUCQ-61 traffic is not charged to, or claimed to fit within, this story's collection budget.
- [ ] **Publication.** The corpus is published as versioned artifacts through FUCQ-54's loader (`manifest.json` and `configurations.jsonl`) and loads through the lookup port. The manifest's count matches the verifier's count.
