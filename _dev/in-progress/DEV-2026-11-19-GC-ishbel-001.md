goal:
  Implement skeleton loading in the Angular app (`apps/gcsp-web`) the same as the Node app. Every screen should show a skeleton shaped like the coming view while it loads, not a status box or loading text.

  Context:

  The Node app draws `loadingSkeleton` (`blocks/gcsp/kit/loading-skeleton.js`) while a portal page loads: `mountEmployee` for account startup, order progress (`timeline`), offer (`offer`), media and release grids. The Angular port already has `LoadingSkeletonComponent` (`div[gcspLoadingSkeleton]`, FUCQ-555, all 12 layouts), but only the offer, help, release and suitability screens use it. Other screens still show `gcsp-status-screen` or loading text while loading, for example account (Your cars), activity, orders, comparison, case queue, Greg's demand/policy, order plan, production status, outbox and manual route.
acceptance:
- [ ] Every Angular GCSP screen with a loading state shows `LoadingSkeletonComponent` in the layout matching that view (as in Node where Node has one), with one announced label and no status box or bare loading text.
- [ ] Ready, empty, error and access-denied states are unchanged; only the loading state changes.
- [ ] Reduced motion and existing focus/stale guards behave as they do now.
files_or_areas: `apps/gcsp-web/src/app/**` screen templates and their specs; `apps/gcsp-web/src/app/kit/loading-skeleton.component.ts` (reuse; extend only if a screen needs a layout Node already has).
decided: Reuse the existing Angular `LoadingSkeletonComponent` and the Node layouts in COMPONENTS.md; no new primitive.
out_of_scope: New layouts Node doesn't have, data or API changes, any change to non-loading states.
validate:
  Focused specs for each changed screen's loading state; `npm --prefix apps/gcsp-web test` for the changed feature folders. Full suite deferred to batch.
