title: Java OIDC: duplicate scope gives 500, unknown kid refetch throttle, no...
work_item_type: bug
related_story: FUCQ-455
story_link_basis: FUCQ-455 built the Java OIDC validation these findings come from.
reproduction_steps:
  1. Send a validly signed token with `scope="openid gcsp-api gcsp-api"`.
  2. Send tokens with random unknown `kid` values in quick succession.
expected_behaviour:
  1. The duplicate-scope token is authorised normally.
  2. Unknown `kid`s get 401, with at most one JWKS refetch per reprieve window.
actual_behaviour:
  1. `Set.of(s.trim().split("\s+"))` throws `IllegalArgumentException` on a repeated value. `authorize()` catches only `MalformedClaimException`, so the request returns 500 `unexpected`.
  2. jose4j refetches the JWKS for each unknown `kid`, up to one fetch per 300 ms under a lock. That gives about 3 IdP requests a second, requests queue behind the 2-second timeout, and a forged token gets 503 `identity-keys-unavailable` while the IdP is down.
  3. No test covers rotation or the unknown-`kid` 401.
