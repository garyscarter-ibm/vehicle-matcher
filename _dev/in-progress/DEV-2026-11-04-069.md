- [x] Browsing never reserves. An explicit Review/select action conditionally claims one exact released vehicle after revalidating current employee/driver eligibility, entitlement limits, draft/stock versions and terms. Two competing employees or tabs produce at most one active holder; retries are idempotent.
- [x] Store server expiry timestamps and configurable, separately named manual preview and order-review timing semantics. Their precise defaults/transition are documented demo assumptions pending SAN-017, not screenshot seconds or the buddy's proposed two-hour hold. Moving between views or refreshing cannot reset expiry.
- [x] Define replace/change/back/cancel behaviour: no silent second hold, no abandoned leaked claim, and a released car becomes available only after confirmed release. Expiry reconciliation works on server reads/commands, startup and explicit demo clock ticks without an active browser; do not claim unattended scheduling on a sleeping host.
- [x] Use the same authority/ports planned for future buddy access, without implementing buddy allocation. For remote-shaped adapters persist uncertain claims/releases as pending, reconcile before retry/reallocation and never turn a timeout into success or an available car.
- [x] Expose current claim/status/quote reads for reload and concurrent sessions; isolate fictional principals/runs and reject stale or cross-principal commands. Reset is an explicitly authorised synthetic-run fixture operation and cannot touch operational providers.
- [x] Record a minimal synthetic policy/stock fixture plus deterministic clock and repository contract evidence. Missing or failed storage returns clear unavailable/pending outcomes, never a fake successful reservation.
