## Checkpoint (2026-11-17, reopened build, story-lead Hippety Hopper)
Gap assessment on base 33115d18c (gcsp-poc-dev):
- routes: `POST offers/:offerId/decision` and `GET offers/:offerId/decision-reasons` are registered (OffersResource). `GET offer-followup` and `POST offer-followup/confirm` are not registered anywhere in Java.
- decline: `offer.declineReasons.v1` and `offer.followupQuestions.v1` exist only in `server/gcsp/policy/reviewed/`. Java never adopts them (Node does, in `offer-journey-adoption.js`, as successor `<base>+offer-journey-v1`), so a deployed decline and reasons read answer 503 `decline-reasons-unavailable`. `offer.declinedCar.exclusion` is in the seed, so the exclusion is bound.
- clock: offers read `PolicyClock`, which in production is `WallPolicyClock`. Holds and quotes are stamped from the run clock (the ticks), so after the first wall-clock hours every deployed offer reads as expired. Accept and decline cannot be met in the deployed composition without offers reading the run clock.
- journeys: no started-app accept/decline journey exists. Only PG-level tests, plus Gary's remote-offer HTTP tests on a fixture clock.
Plan (slices in `.product-map/work.json`): decline = Java offer-journey adoption through PolicyService at startup when `GCSP_POLICY_VERSION` names `<base>+offer-journey-v1`; accept = offers read the run clock; followup = the two `offer-followup` routes ported from Node `followup.js`; integration = started-app JWT/PG journeys for AC1 and AC2 over the FUCQ-464 Buddy journey infrastructure, with `OffersTestPorts$Records` excluded.
