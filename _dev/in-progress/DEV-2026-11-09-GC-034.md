decided:
  diagnosis (story-lead, 9 Nov 2026, base 168a0582): reproduction: FUCQ-248 run 2 walk (sections-run2.mjs), Next release from
  the strip on /gcsp-activity-live.html leaves "No current offer" until reload (run2-activity-1280-02 against -03, both viewed);
  order progress needs a reload per Tick. Cause: the strip (presenter-controls/controls.js) dispatches a bubbling
  `gcsp:presenter-action` CustomEvent on success (not on reset or principal switch), but only the presenter workspace's Greg
  branch, the offer page (adapter.subscribeClock) and the manual journey's gallery/review/setup/summary views listen. The
  activity live entry (activity/live.js), order-progress live entry (order-progress/live.js) and the journey's account view
  (journey.js subscribeClock callback skips `account`) never subscribe; the outbox and the standalone Greg harness do not either.
  Their only re-read paths (`refresh()`) first paint a loading screen, which drops focus to main and collapses scroll, and the
  account refresh remounts the whole shell including the strip. Server data is correct (a reload shows it), so the fault is
  client wiring only. Impact: activity, order progress and account card stale between presenter actions; no data repair needed.
  Repair: subscribe once per page to presenter actions and run a quiet re-read (no loading paint) that keeps focus by key and
  scroll, announcing once in a polite live region; pages with no presenter-driven data (brief, help) stay unsubscribed.
