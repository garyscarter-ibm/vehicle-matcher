  Cause/evidence: presentation only. Offer, quote and outbox rows are correct; the rendering is at fault.
  (1) server/gcsp/notify/templates.js reads quote.facts.model/modelName/name, but buddy quotes store the car under
  quote.facts.display (name/model/derivative), so every offer email falls back to "Your scheme vehicle"; it never
  reads quote.terms.points; it prints offer.expiresAt raw (ISO); it greets with employee.name, which carries the
  fixture marker "(fictional)". (2) The offer link is minted relative (offer-token.js, GCSP_OFFER_LANDING_URL default
  /gcsp/offer); only BrevoMailTransport makes it absolute (GCSP_PUBLIC_BASE_URL), CapturedTransport stores it
  relative, so the offline email shows an address no mail client can open. (3) Outbox viewer
  (blocks/gcsp/presenter/outbox-copy.js STATUS, message-list.js) labels state "sent" as "Sent" whatever the
  transport, while the captured footer says "No email has been sent"; the outbox route projection drops
  job.transport. (4) .gcsp-mail-frame (gcsp-presenter.css) has no focus style; sandboxed iframe is a tab stop.
  Affected writers/readers: renderOfferMessage (dispatcher, comparison harness), CapturedTransport, Brevo transport
  (rewrites relative link and footer by exact string), outbox route projection, presenter viewer and fixtures,
  critical-path test (parses "available until <ISO>."). Existing data: captured messages already stored keep old
  copy until a demo reset; no migration needed. Origin: outbox viewer FUCQ-97 (commit 9a661ac2); template from
  f4c5355e (story not named in commit). Deadline wording uses Europe/London, the zone the outbox viewer already
  uses for demo-clock times; no shared server formatter exists on gcsp-poc (FUCQ-267/268 not landed), so it stays
  local to the email template.
