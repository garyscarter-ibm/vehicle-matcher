goal:
  Found while building FUCQ-136. Confirmed on gcsp-poc 445e09ce, seed comparison-a, with the shallow snapshot on.

  **Cause:**

  * The prepare transaction records a single `buddy-allocation` receipt holding `plan.contenders` and `plan.evaluations`.
  * `contenders` carries a full quote for every eligible participant and car pair: snapshot, terms, employeeFacts, reasons and tradeOffs.
  * `evaluations` carries a decision with reasons for every participant and available car, about 750 x 100+ at this cohort.
  * The repository's `inputDigest` calls `JSON.stringify` on that receipt. The receipt exceeds V8's string limit of about 512 MB, so the call throws `RangeError: Invalid string length`.
  * `core.js:340` catches the error silently and returns `unavailable` ("Repository is unavailable"). `allocate` reports unavailable after 50 to 100 s, at about 2.5 GB RSS.

  **Impact:**

  * This blocks FUCQ-136's 1,000-employee buddy measure, and with it the stored comparison result.
  * The live demo is not affected at its size.

  **Recommended fix (about 5 points; risky path, so keep it separate like FUCQ-205):**

  * Store each employee's evaluation slice as its own receipt row, and point the readers `offers/followup.js:151` and `brief/activity.js:70` at those rows.
  * Keep contenders compact: store an attempted contender's quote only when it is claimed, or rebuild it from that employee's slice under the same `expectedVersions`.
  * Behaviour must not change: same tie-break, same idempotency, same FUCQ-96, FUCQ-100, critical-path and FUCQ-205 tests.
