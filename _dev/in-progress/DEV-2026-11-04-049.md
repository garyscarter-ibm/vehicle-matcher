goal: As Paula, I want my confirmed brief saved as a version, together with my permission to search and hold, so that the buddy acts only on what I approved.
acceptance:
- [x] **BriefService:** a service over FUCQ-81's repository that can:
  save a draft;
  confirm it as a new immutable version;
  revise it by creating a further version;
  read the current version and its history.
  The shape follows the brief schema in `docs/gcsp/shared-contracts.md`. Every brief carries the employee and `runId` from FUCQ-84's server-owned context.
- [x] **Fields:**
  preference values per dimension, each with its separate importance or indifference weight;
  confirmed essentials (carrying, equipment, charging readiness);
  prefilled known facts, with their source;
  explicit consent to search and to hold (buddy on/off);
  a paused flag.
  Drafts and inferred suggestions stay separate from confirmed versions. An unknown essential stays unknown and is never defaulted.
- [x] **Gates through PolicyService:** gate checks read PolicyService keys and FUCQ-29's gates. Charging that is not ready or unknown excludes plug-in cars until it is resolved; that rule is a labelled demo assumption key. No contribution question appears, because Choices is points-based (Q16).
- [x] **Stale and unconsented saves:** a stale write is rejected with a refresh outcome. Confirming without consent saves the brief with the buddy left off.
- [x] **Pause and resume:** both are versioned state changes. Pausing stops new searches and holds. An existing offer is unaffected, and the response reports it.
- [x] **Single post-decline change (Q16):** a dedicated operation records which one field changed, from what to what, and the decline it answers. O4 (blueprint 07) uses it.
- [x] **Events:** a confirmed version, a change, a pause or a resume each record a brief-changed event receipt. Allocation reads it.
- [x] **Routes:** `/api/gcsp` routes read the current brief, save a draft, confirm, and pause or resume, all using server-owned context. Another employee's brief is refused, and browser-supplied employee or run IDs are ignored.
