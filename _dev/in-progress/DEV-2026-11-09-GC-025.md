  Severity: Medium. Found while verifying FUCQ-171 (merge ff554bba on gcsp-poc, 9 Nov 2026).

  **Steps to reproduce:**

  1. Enable return outcomes (`lifecycle.return.outcome.v1`) with outcome `missed`.
  2. Run the return-outcome tick so the return is recorded as missed. The renewal-risk tick then opens a case.
  3. Open the case as Greg or Paula.

  **Expected:** the case says the old-car return was missed.

  **Actual:** the case reads "Opened from Missed handover appointment", with the raw `lifecycle-exception` trigger and a generic reason. This happens because `lifecycle.return.outcome.v1` reuses the exception type `appointment-no-show`, so the case cannot tell a missed return from a missed handover.

  **Likely fix:** give missed returns their own keyed exception type, with matching labels in `renewalCase.lifecycle.eventTypes` (policy), keeping the receipt keyed as today.

  **Impact:** post-demo lifecycle only; return outcomes are off by default.

  Related story: FUCQ-168 (origin). Found in FUCQ-171. It does not block their review.
