goal:
  FUCQ-466 added offer accept and decline to the Java API. Decline needs the reviewed registry of decline reasons and follow-up questions. In Node, `offer-journey-adoption.js` adopts that registry. Java has no equivalent, so in a default deployment decline answers 503 `decline-reasons-unavailable`, and GET reasons answers the same.

  Acceptance:

  * Java can adopt the reviewed decline-reason and follow-up registry, with the same shape and versioning as Node's offer-journey adoption.
  * With the registry adopted, decline succeeds and GET reasons returns the list.
  * Without it, the honest 503 stays.
  * Add a parity test against the Node adoption cases.
