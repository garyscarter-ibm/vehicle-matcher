  Found by FUCQ-435's cross-origin browser proof (17 Nov 2026) against the composed Angular app and Java API on gcsp-poc-dev. Evidence and screenshots: `docs/gcsp/evidence/fucq435/2026-11-17/` (scenario i).

  **Behaviour:** opening any offer, including from an emailed link, shows "Offer link incomplete".

  **Cause:** Angular `apps/gcsp-web/src/app/offers/offer.client.ts:74` reads `/offers/{id}?runId=<context.runId>`, and decision-reasons does the same. Java's `OffersResource` (lines 55, 69, 83) refuses any query parameter with `unsupportedQuery()`, which answers 400. In Node, `server/gcsp/offers/access-http.js:68` and `decision-http.js:67` accept exactly one optional `runId` and refuse anything else.

  **Expected:** Java accepts a single `runId` query on the offer read routes, as Node does. A `runId` that is not the principal's active run is refused truthfully, and any other parameter is still refused.

  **Impact:** offers can't be opened in the composed app. That breaks the email-link journey (FUCQ-469 AC2) and accept/decline (FUCQ-466) in the browser, even though the Java API journeys pass without the query.
