  ## Symptom

  `server/test/gcsp-case-release-http.test.js` has four "C4 …" tests, authored on 6 Nov on the FUCQ-122 branch. All four fail at `release()` (line 92) with `'held' !== 'released'`. They came into gcsp-poc with the FUCQ-122 merge on 8 Nov, and were then skipped so base stays green.

  ## Cause

  After the release tick, the helper expects the stock row in state `released`. Since FUCQ-118, `buddy-allocation` runs in the same tick, after `selection-order-reconciliation`, so a consenting employee's matching car is `held` by the time the test reads it. The product behaviour is right; the test's expectation is stale.

  ## Repair

  Update the helper and the later assertions to expect the allocated state, or read the row before allocation runs. Then remove `test.skip` and the two-line comment, and run the file alone, serially.

  ## Impact

  Test coverage only. No demo-visible effect.
