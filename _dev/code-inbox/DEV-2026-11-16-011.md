  Found by the concurrency review of FUCQ-421 (merged into gcsp-poc-dev at 0431d674). Three Low findings:

  1. **Shared** `runs` revision row (`0010_repository_revisions.sql` lines 13–18). Every transaction that writes any `runs` row now locks one shared row until it commits.

      * Scenario: a long reset of environment E1 holds the lock through its whole flush. A clock advance in E2 waits behind it and may hit the 10 s `statement_timeout`, returning `unavailable`.
      * Fix: accept and document this, or move the `runs` table bump to just before COMMIT.

  2. **Trigger bypass.** These skip the triggers: `SET session_replication_role = replica`, `ALTER TABLE … DISABLE TRIGGER`, and dropping and re-creating the schema or restoring a backup while instances run. Each can bring revision numbers back to values a cache already holds.

      * Fix: say in the repository README that maintenance with triggers off, or a restore, needs an instance restart.

  3. **Missing native test coverage** in `server/test/gcsp-postgres-run-revision.test.js`. There is no test for DELETE, TRUNCATE, an UPDATE that moves run_id, or a savepoint rollback. The reviewer checked all four by hand and they behave correctly; tests are needed so a future trigger edit can't break them unnoticed.
