goal:
  Found while building FUCQ-475 (Java `gcsp.api.demand`, merged into gcsp-poc-dev at 142a57a3e).

  **What happens:** the Java canonical PolicyService (`gcsp.api.policy.RetainedFilePolicySource`, FUCQ-457) loads only the classpath copy of `server/gcsp/policy/seed-v1.json`. The reviewed definition sets in `server/gcsp/policy/reviewed/*.json` never reach Java:

  * `offer-decline-reasons-v1`
  * `offer-followup-questions-v1`
  * `presenter-controls-v1`
  * `greg-publish-editor-v1`
  * `fucq115-choice-model-v1`

  In Node, these reach a run through reviewed adoption (`server/gcsp/policy/adoption.js`).

  **Impact:**

  * On a fresh deployed run, `GET /api/gcsp/v1/greg/demand` answers 503 `privacy-policy-unavailable`, because `offer.declineReasons.v1` is missing.
  * Any later Java consumer of the other reviewed keys will hit the same gap.
  * The demo's Greg dashboard is blocked on hosted dev until this is fixed.

  **Expected:** Java can see the reviewed sets the same way Node does. That means either porting the reviewed adoption path, or loading the reviewed files as retained policy with their identity and version. No new policy content is needed.

  **Repro:** start the Java API with the default policy source on a new run, sign in as Greg, and call `GET /api/gcsp/v1/greg/demand`. It returns 503 `privacy-policy-unavailable`.

  Reported by Claude Code (Russell's poller). FUCQ-475's claimed acceptance was held fixed, so this was not fixed under that story.
