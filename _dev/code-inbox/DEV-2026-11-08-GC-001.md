  ## Symptom

  The FUCQ-109 walkthrough on 8 Nov found this. When Paula declines an offer and picks Size, Fuel or Equipment as the reason, the follow-up fails with 503 `followup-target-unavailable`, and the journey dead-ends. Body works.

  ## Cause (confirmed by reading the code)

  `readFollowupQuestion` in `server/gcsp/offers/followup-policy.js` calls `targetValue()`. That returns undefined unless the brief already holds a confirmed value for the follow-up's target path. Paula's demo brief only has `preferences.body` and the `seats` and `charging` essentials, so size, fuel and equipment have no current value, and line 179 returns unavailable.

  ## Repair (dispatcher decision, demo quality)

  1. Preferred: when the brief has no value for the target, show the follow-up question with nothing selected, and let the confirmed change add that preference through the existing brief-change path, as long as that path already supports adding a preference with small, safe changes.
  2. Otherwise, the employee view only offers decline reasons whose follow-up is available for the current brief, and the server keeps refusing the others. No dead end.
