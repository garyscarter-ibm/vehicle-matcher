  Found by FUCQ-435's cross-origin browser proof (17 Nov 2026) against the composed Angular app and Java API on gcsp-poc-dev. Evidence and screenshots: `docs/gcsp/evidence/fucq435/2026-11-17/`.

  **Behaviour:** the manual order review page shows "Review unavailable" for every claim.

  **Cause:** Java returns the claim's `hold.mode` as `local` (or `remote`). That field is the claim adapter mode, set in `ManualClaims.java:498` and emitted by `ClaimRow.hold()`. Angular's `account.types.ts:51` types `hold.mode` as the journey mode `'new' | 'replacement'`, and `manual-review.component.html` branches on it, so the projection rejects the payload. In Node, `new`/`replacement` is the journey's `choices.mode` (`server/gcsp/manual-context/index.js:192`), and the adapter mode (`local-synthetic`/`remote`) is not exposed as `hold.mode`.

  **Expected:** the claim payload carries the journey mode Angular expects, matching the Node contract, and the review page renders.

  **Impact:** the employee manual order journey can't reach review in the composed Java plus Angular app. Hosted dev would show the same.
