  On 8 Nov, Render killed gcsp-api about 30 s after `node index.js` with "Out of memory (used over 512Mi)". This happened at commit 9fcfcb23, with GCSP_RUNTIME=1, memory mode and corpus release 2026-11-07.12.

  Measured locally at the same start-up, in hosted runtime and memory mode: peak RSS 489 MiB, and about 445 MiB once /health/vehicle-evidence is ready (around 25 s).

  Demo workaround: run gcsp-api on Render Standard (2 GB). The Starter and Free plans are both 512 MB.

  After the demo, find where the memory goes and cut it so the service fits in 512 MB with headroom. Candidates: the whole 10,000-configuration corpus held as parsed JSON, duplicate copies during load, or the memory repository seeding. Then add a start-up memory check to CI.
