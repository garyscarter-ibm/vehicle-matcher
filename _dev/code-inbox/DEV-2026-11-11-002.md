goal: As Paula, I want the exact selected options, paint and upholstery to have readable names when an offer is generated, so that I can compare its configuration with my current car.
acceptance:
- [ ] Seed a versioned local lookup of supported option, paint and upholstery codes for the admitted demonstration configuration population. Retain source/date, model/market/configuration applicability, definition version and known gaps; ambiguous codes cannot silently resolve across incompatible variants.
- [ ] Reuse synthetic-registry getConfiguration and the indexed-jsonl configuration-ID lookup. Resolve selected codes using prebuilt/local keyed lookups at generation/enrichment time, without scanning the entire catalogue or calling an upstream service once per offer. Seed/load failures and unknown code/identity remain explicit.
- [ ] Return readable selected-option, paint and upholstery facts (and supported swatch values) through the existing vehicle-evidence adapter contract, including exact configuration association and provenance. Equipment presence comes from that configuration's selected set, not a model-wide list; selected catalogue configuration does not become verified physical-car fitment.
- [ ] Join before a new quote is pinned, working with FUCQ-382's corrected stock-to-offer snapshot path. Existing vehicle objects and current/offered comparison consumers can use the supported definitions; preserve unknown versus absent/not fitted, and do not mutate/reprice existing pinned/historical quotes when the active dictionary changes.
- [ ] Demonstrate two same-model configurations with different selected options resolve differently, supported paints/upholstery resolve by their own codes, and missing/ambiguous definitions stay concise and truthful in the downstream offer comparison. Capture population coverage and unresolved codes without claiming a complete manufacturer's build sheet.
- [ ] Record corpus/definition identity, coverage and evidence that repeated offer lookups reuse the keyed index rather than rescanning or making per-offer upstream requests. No new performance benchmark or latency SLA is required.
