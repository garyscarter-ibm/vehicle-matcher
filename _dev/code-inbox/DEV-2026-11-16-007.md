  **Found by:** the FUCQ-458 Java port (Claude Code dev poller, DEV-2026-11-13-026, merged at 56be0c88).

  **Behaviour:** the Node manual-context check `closedDates?.includes(date)` also matches when `closedDates` is a string, because `String.prototype.includes` does a substring match. A malformed source value such as `"2026-11-142026-11-15"` would therefore count as closing dates by substring.

  **Java:** the Java account port copies this exactly, so that it matches the Node baseline's output. The change is not fixed in the migration.

  **Severity:** Low. Sources normally supply arrays, and no observed fixture is affected.

  **Suggested fix:** require an array of ISO dates and refuse anything else as an invalid source, in both Node (if still live) and Java (`gcsp.api.account`), with a regression test.
