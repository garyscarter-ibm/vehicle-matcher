reproduction_steps:
  Source-derived sequence, not an executed runtime reproduction:

  1. Open the employee preferences editor and start an unsaved-draft preview using the current brief/draft versions.
  2. Before that preview resolves, save and confirm the preferences through saveFull().
  3. Allow the old preview to return stale-version while the successful save's final readback is pending, or before the next preview dispatch.
  4. Complete the current successful editor readback and inspect the failure/locked state.
expected_behaviour: A superseded preview cannot replace the recovery state of a successfully saved and refreshed editor. Server-owned versions and genuine current conflicts remain authoritative; stale writes must still be refused.
actual_behaviour: requestPreview() only checks its preview ticket and session/context lifetime. saveFull() does not invalidate that outstanding preview. The old stale-version result can call fail(), setting shared failure and making locked() disable controls. The successful final readback does not clear that intervening failure. Refresh repairs the transient client state. No persisted data loss, ownership bypass or persisted-state repair has been established.
