  Found by Russell's poller on 17 Nov 2026 during the FUCQ-433 reopened builds (FUCQ-454, FUCQ-469, FUCQ-456).

  **Behaviour:** about 21 `@QuarkusTest` profiles in `services/gcsp-api/src/test/java` hard-code the database name `gcsp_test_dev`, instead of taking it from `GCSP_TEST_DATABASE_URL`. Examples: `account/AccountDevCompositionProfiles`, `allocation/BuddyJourneyProfiles`, `brief/BriefJourneyProfiles`, `cases/CaseCompositionProfile`, `documents/DocumentsTestProfile`; `git grep gcsp_test_dev services/gcsp-api/src/test` lists them all. When a lead points the tests at its own database, these classes error at boot rather than run. FUCQ-454 saw 2 errors, FUCQ-469 7 and FUCQ-456 6.

  **Impact:** test-only. Scoped runs report errors that aren't real failures. Parallel story runs can't isolate their databases, and either share `gcsp_test_dev` or need a throwaway cluster. Production code is not affected.

  **Expected:** every profile derives its database from `GCSP_TEST_DATABASE_URL` (and `GCSP_TEST_RUNNING_DATABASE_URL`), as the README test section describes.

  **Repro:** set `GCSP_TEST_DATABASE_URL` to a database with any other name and run `./mvnw -B test -Dtest='gcsp.api.**.*WiringTest'`. RealPortsWiringTest and PersistenceWiringTest error at boot.
